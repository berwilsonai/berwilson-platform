Then confirm: `git log --oneline -1` and check the app responds. If `npm run build` fails, do NOT kickstart — the old build stays live; fix the error first. Always `git pull --ff-only` before starting a fresh editing session. Full host/infra detail lives in the `self-hosted-mac-studio-deployment` memory.

### AI Model Rules (CURRENT — FULLY LOCAL since 2026-07-07)

**The platform is fully self-hosted and fully local-AI as of the 2026-07-07 cutover** (Richard's decision: absolute security, nothing leaves his hardware). Production = the Mac Studio, tailnet-only: app at `https://richards-mac-studio.tail9acc02.ts.net/`, self-hosted Supabase at `:8443`, LM Studio on localhost:1234. **(The MagicDNS suffix changed `tail0e5306` → `tail9acc02` on 2026-09-16 when the tailnet moved to the berwilson.com Workspace org; the Studio is now `100.102.45.39`. Dated entries below still name the old values — that is history, not current state.)**

- **All runtime AI** → `qwen/qwen3.6-35b-a3b` via LM Studio's OpenAI-compatible API (`AI_PROVIDER=local`, `src/lib/ai/local.ts`). Expect ~30–60s on extraction-class tasks (reasoning-heavy model, ~75 tok/s generation).
- **LM Studio load configuration is load-bearing and resets on an eject/reload** — assert it with **`zsh deploy/lmstudio-check.sh`** (`--fix` reloads at the documented settings), which is now part of the deploy runbook. Found drifted to **173,824** on 2026-09-30, costing +1.38 GiB on a box down to 314MB free with 10.7 of 12GB swap in use, for a window the agent cannot reach (`AGENT_CONTEXT_BUDGET_CHARS` caps a conversation near 88k tokens). Settings (2026-09-26): `--ctx-size 131072` with `--cache-type-k q8_0 --cache-type-v q8_0` — the q8_0 cache is what pays for the doubled window, costing +2.12 GiB over 65,536 f16 rather than +5. `AGENT_CONTEXT_BUDGET_CHARS` and `AGENT_DOC_WINDOW_CHARS` in `.env.local` are sized to it and must move with it. **Check `lms ps` after any reload:** a model id ending `:2` means a SECOND 22GB copy is resident (41GB against 36GB of RAM — seen live), and `--parallel` reverts to 4 whatever it was set to.
- **Embeddings** → `text-embedding-qwen3-embedding-0.6b` at its **native 1024 dims**, stored in `vector(1024)` on BOTH `chunks` and `thread_chunks`. The width lives in ONE place — `EMBEDDING_DIMS` in `src/lib/ai/local.ts` — and must equal the schema; when they match, `localEmbedding` returns the model's vector untouched (the truncate+renormalize branch only runs if `EMBEDDING_DIMS` is deliberately made narrower). **Never mix embedding models OR widths** — either change means wipe + re-embed BOTH tables (`deploy/reembed.mjs`), never one of them. **A chat model, by contrast, is swappable at will**: nothing is fine-tuned, all knowledge is in Postgres, so a better `LOCAL_AI_MODEL` costs nothing to adopt.
- **Company knowledge base** → fed by the nightly Drive sync over `GOOGLE_DRIVE_KNOWLEDGE_FOLDER_ID` (142 of 154 live `is_company` documents; email attachments NEVER land here — `importThreadAttachments` returns 0 for any thread not linked to a project or opportunity). **`documents` AND `opportunity_documents`** both carry `excluded_at`/`excluded_reason` (a human's "not knowledge" — the ROW IS THE TOMBSTONE, §12) and `filing_confirmed_at` ("it is right where it is"); the second table got them 10-14, and until it did, a filing audit over both ran GREEN and reported all 103 of those documents clean, because PostgREST answered `42703` and the caller read `data` as null. **An opportunity's documents are their OWN TABLE** — `documents` has no `opportunity_id` — and `chunks` reaches them through `opportunity_document_id`, so a count on `document_id` returns 0 and zero reads as "never indexed". `refileDocument`/`excludeDocument`/`confirmDocumentFiling` in `src/lib/documents/refile.ts` take a `DocumentSource` that defaults to `documents`; re-filing re-points chunks and never re-embeds. **Where a document BELONGS is asked in one place** — `matchDocument` in `src/lib/documents/match.ts`, serving the company-knowledge queue (`unfiled.ts`), the wrong-deal queue (`misfiled.ts`) and the mail sweep's per-attachment target.
- **Office files** → read directly, no model call: `.docx` via mammoth, `.xlsx` and `.pptx` via `fflate` over the OOXML (`src/lib/ai/document-text.ts`). pptx was added 2026-09-27 — before that `documentKind` had no branch for it and decks were skipped with no `documents` row created at all.
- **PDFs** → local text extraction via `unpdf` (no model call for transcription). **Scanned PDFs and images → Apple Vision OCR** (`bw-ocr`, `scripts/ocr/card-ocr.swift`), spawned like whisper.cpp: renders each page at 200 DPI and recognizes it. No model, no RAM held resident, nothing leaves the machine — the 11-page scanned Alaska mining lease read in **3 seconds**. **A vision LLM is deliberately NOT used and there is no room for one:** the box is 36GB, llama-server holds 19.7GB of weights plus 5GB of KV cache, Colima reserves 3GB, and swap already runs full. OCR is also simply better at dense printed text.
- **Web research / enrichment** (`research.ts`) → blocked in local mode unless `LOCAL_ALLOW_WEB_RESEARCH=true` (Gemini + Google Search). Currently ON for the Enrich Profile buttons. "Only the query leaves" was **prose and nothing else until 2026-10-11** — the arg went out verbatim, unchecked and unlogged, and `run_research` let the MODEL compose it. Now every outbound query passes `guardOutboundText` (`src/lib/security/egress.ts`, refuses a protected project's name, fails closed) and lands in `ai_queries`, refusals included.
- The Gemini path in `gemini.ts` survives behind `AI_PROVIDER` but only web research reaches it (`gemini-2.5-flash` + Google Search grounding in `research.ts`); its pre-cutover roles — extraction, classification, the agent loop, `gemini-embedding-001` at 768 dims — are history, see the log. Cloud Supabase project `qauclkrdejgtpywqixho` is **paused** (restorable safety net); the Vercel project is **deleted**.

Anthropic Claude is not used at runtime (removed 2026-06-22). **Every AI call logs to `ai_queries`** (user, prompt, response, model, tokens, latency) — keep that contract when adding calls.

## 4. DATABASE SCHEMA

**Source of truth is `src/types/database.ts`, and it covers every table** — 104 of 104 on 10-14, regenerated from the live schema. ⚠ Count it (`gen-types` prints both figures and asserts they match); the number written here was 97 four tables ago. Regenerate with `npm run gen-types` (→ `deploy/gen-types.sh`), which reads `SUPABASE_DB_URL` or falls back to the running container, asserts it reached THIS database and covered every live table, and refuses to overwrite the file while it has uncommitted changes (two sessions share this repo). `-- --force` is the deliberate override.

**Row types come from the schema, not from hand.** Six modules carried 1,290 lines of hand-maintained row interfaces while gen-types was disabled; they are now aliases of the generated `Row`, with `Refine<T, R>` (in `src/lib/supabase/types.ts`) overriding only the jsonb/array columns a module narrows and the CHECK-backed unions the generator can only call `string`. `LeadRow` is the one interface still written out, because it is mostly per-field documentation — two `AssertNever` assertions make it unable to drift and name the column when it does. **Write jsonb with `JsonIn`, never `Json`:** `Json` includes null and a NOT NULL jsonb column does not. **Never add an `as never` cast** — there are zero, and this section has forbidden them all along. The untyped `createUntypedAdminClient()` survives for dynamic-table and embed-heavy reads the generated client cannot infer; the TYPES no longer depend on it.

Migrations live in `supabase/migrations/` numbered chronologically. ⚠ This line read "41 as of this writing" against **156** files — a hand-incremented count drifts silently, so `ls supabase/migrations/*.sql | wc -l` rather than trusting a number written here.

### Conventions (unchanged)
- All PKs: `id uuid default gen_random_uuid() primary key`.
- All timestamps: `timestamptz default now()`, UTC.
- RLS enabled on every table.
- `activity_log` is append-only — no UPDATE/DELETE policies, ever. **A DELETE therefore survives itself**: `log_activity()` writes `to_jsonb(old)` into `metadata`, so a hard-deleted row is recoverable from the log. As of 2026-09-30 the trigger also does a **generic column-by-column diff** for twenty governance tables (named in `_audited_in_full` inside the function) — gated to a list, because `documents`/`updates` carry hundreds of KB of text and diffing those would store both copies on every edit.
- `updated_at` auto-maintained by trigger; tracked tables auto-insert into `activity_log` via trigger.

### Table groups (read database.ts for columns)
- **Core CRM:** `projects` (with `parent_project_id` hierarchy, `bid_due_date`, `win_probability`, capture fields), `project_players`, `milestones`, `updates`, `documents`, `dd_items`, `financing_structures`, `compliance_items`, `project_dependencies`.
- **Tasks (2026-06-25):** `tasks` (real task model — title/what/why/how/assignee_id/project_id/due_date/status/completed_at), `task_notes` (per-task notes feed), `team_members` (assignee list, seeded Richard/Eric). Replaces the old `updates.action_items` JSON for the task UI.
- **Shared children (2026-09-23):** `project_players`, `milestones`, `dd_items`, `financing_structures`, `entity_projects`, `compliance_items` and `research_artifacts` hang off **either** a project or an opportunity — nullable `project_id` + nullable `opportunity_id`, with a check constraint (exactly-one for the first five, at-most-one for the last two). `milestones.stage` is plain **text**, not the `project_stage` enum, so one table carries both pipelines. Never assume `project_id` is set on these.
- **Directory:** `parties` (people + orgs via `is_organization`), `contact_aliases` (uniqueness is on the generated `alias_key` = `lower(alias)`; conflict on `alias_key`, never `alias`), `entities` (legal entities/vendors), `entity_projects`, `party_entities`, `certifications`.
- **Capital raise (2026-07-10):** `investors` (relationship pipeline, links to `parties`), `investments` (investor × target), `investor_notes`. **`target_kind` is company | project | `spv`, and an spv-targeted row sets `spv_id` → `project_spvs` with `project_id` NULL** (2026-10-08) — the deal is reached THROUGH the vehicle, which is the only way a commitment can attach to an opportunity at all. `spv_entity_id` is **dropped**: it pointed at `entities`, the legal company, so the same LLC on two deals made the pointer ambiguous. ⚠ **`investments` IS THE RAISE PIPELINE AND `project_spv_participants` IS THE CAP TABLE** — who we are talking to vs who holds what. They join on `investor_id`, are shown side by side with the overlap counted, and are NEVER summed: the same dollar legitimately sits in both.
- **Steel CRM (2026-07-25):** `steel_deals` (prefab steel deal pipeline: quote→engineering→order_placed→delivered→paid, lead source, salesperson FK→team_members, sqft/$SF/value), `steel_deal_notes`. Own role `steel_sales` sees only this module.
- **Dino (2026-07-28):** internal operating company (acquired plumbing/HVAC co, dinoservicepros.com — NOT a vendor). `dino_revenue` (source_type internal|external; internal → FK project_id, external → client_name; per-job or periodic lump), `dino_payments` (the $150k/12-mo obligation schedule), `dino_notes`. Tracks the internal-vs-external revenue split (show Dino its revenue increasingly comes from Ber Wilson) + money we owe them. Admin-only. See build-status.
- **Land (2026-09-28):** `project_parcels` (the parcels a project or opportunity is made of — county parcel id, TWO acreage columns for the deal's figure and the assessor's, status, zoning, GeoJSON Polygon/MultiPolygon + centroid). Geometry is imported by parcel id from Utah AGRC's per-county LIR layers (`src/lib/parcels/agrc.ts`), never traced.
- **Lead routing (2026-09-30):** `lead_categories` — THE registry of lines of business, one row per lane. Carries `destination` (project | opportunity | steel_deal | handoff | manual), `routing_rule` (read to the triage model verbatim), `handoff_email`, `drive_folder_id`, `share_with`, `publish_sheet`, `tone`, `active`, `system`. **`leads.route` is an FK to `lead_categories.key`** with `on update cascade` (a rename carries its leads) and no delete rule (a lane with leads cannot be deleted — that is what `active=false` is for). Adding a line of business is an INSERT at `/settings/lead-categories`, never a code change.
- **Vehicles / SPVs (2026-10-06):** `project_spvs` is the SPVs a deal is held in — a child of the **project or opportunity** (shared children, `unique nulls not distinct (project_id, opportunity_id, label)`), **not of the economics model**, so the structure is settled before anything is priced and survives a model being rebuilt. `purpose` is land | energy | data_center | housing | other; nullable `org_node_id` links it to the corporate chart with `org_node_name` snapshotted beside it; `raise_target` is a goal and never a rollup. `project_spv_participants` is the ledger that answers participants, equity splits AND capital raise at once — one row per holder with `equity_pct`, `capital_committed`, `capital_funded`, a nullable `investor_id` seam to the raise machinery, and **`is_ber_wilson`, a FLAG and never a name match**, with at most one per vehicle. **Our share is DERIVED** by `resolveBwShare` in `src/lib/spvs/ownership.ts`: the flagged row when a ledger exists, the typed `bw_ownership_pct` when it does not, and it reports WHICH it read. A ledger with no flagged row is **undetermined, never the residue of the others**. `economics_lines.spv_id` points here. Row types in `src/lib/spvs/db.ts` (`spvDb()` / `spvDbAs()`).
- **Deal economics (2026-10-05):** ten tables answering "how big is this deal, and how much of it is ours". `deal_economics` is one model per project or opportunity (shared children, `unique nulls not distinct` on the parent pair) carrying the deal-level rates and the computed rollups; `economics_capacity_sources` (nameplate, availability, and block designs — 24 blocks of 50 MW at N+4 is 1,000 MW firm, not 1,200), `economics_buckets` (the allocation ledger), `economics_lines` (13 line types in sparse TYPED columns, not jsonb), `economics_line_schedule`, `economics_provenance` (per FIELD: status, source, as-of), `economics_versions` (jsonb snapshots), `economics_benchmarks` + `economics_templates` (registries), `economics_input_proposals` (AI-staged, human-confirmed). **`line_type` is a CHECK and deliberately NOT a registry** — each type is a formula in `src/lib/economics/lines.ts`, so adding one is necessarily a code change. (`economics_spvs` was dropped 2026-10-06 and replaced by `project_spvs` above, with its parent changed.) Eight of the ten carry the audit trigger; `economics_versions` and `economics_input_proposals` do not (see §12 and the `commitments` precedent). Row types in `src/lib/economics/db.ts` (`calcDb()` / `calcDbAs()`).
- **Pipeline value (2026-10-05):** `projects.economics_capture_value` / `economics_status` / `economics_computed_at`, and the same three on `opportunities`. **The name IS the definition:** that column is Ber Wilson NET capture and nothing else. `estimated_value` survives as whatever a human typed and is never overwritten; both are read through `pipelineValue()` in `src/lib/economics/pipeline.ts`, which returns the figure AND which quantity it is. ## 5. AI ARCHITECTURE

### Unified Gemini client — `src/lib/ai/gemini.ts`
- `callGemini({ task, systemPrompt, userMessage, userId, promptVersion?, maxTokens?, jsonMode? })` — text in, text/JSON out. `jsonMode` defaults true (uses `responseMimeType: application/json` + strips stray code fences).
- `callGeminiWithFile({ systemPrompt, prompt, file: { mimeType, dataBase64 }, userId, logLabel?, promptVersion?, maxTokens?, jsonMode? })` — multimodal: a PDF/image plus a text instruction. Used by document and certification summarization.
- Both return `{ data, model, tokensIn, tokensOut, latencyMs }` and log to `ai_queries` (fire-and-forget). When the model returns valid JSON, `data` is the parsed object; otherwise `data` is the raw string — callers should branch on `typeof data === 'object'`.

### Extraction shape
Extraction prompts return structured JSON (summary, action_items, waiting_on, risks, decisions, mentioned_parties, mentioned_projects, confidence). See `src/lib/ai/prompts/extraction.ts`.

### Agent — `src/lib/ai/agent.ts` + `agent-tools.ts`
Local-Qwen agentic loop, `AGENT_MAX_TOOL_ROUNDS` rounds (default 12, the last tool-free — §12). Injects the Ber Wilson company profile into context so the agent knows the company's qualifications without a tool call. Tools are declared in `agent-tools.ts` and executed via `executeToolCall`. Conversations persist to `agent_conversations` / `agent_messages`.

**Construction Executive Agent persona:** senior EVP/COO, 25+ yrs government contracting, large-scale development, design-build GC, prefab, construction finance. An owner-operator, not a consultant. Four lenses on every recommendation: **Commercial** (can we win it?), **Operational** (can we deliver it?), **Financial** (can we get paid, at what margin?), **Compliance** (can we protect the downside?). Response protocol: Situation → Risks → Recommendation → Next Decision. Never ungrounded guesses; never hide risk; never substitute for legal/tax counsel; always distinguish facts, estimates, and judgments.

### Hybrid retrieval (RAG)
Query → SQL filter → vector search (`match_chunks` RPC over `chunks.embedding`) → re-rank (recency/confidence/cosine) → top chunks into context → grounded answer with citations → log to `ai_queries`.

### Proposal matching — `src/lib/ai/proposal-matching.ts`
Dedupes an inbound opportunity against existing `projects`/`parties` (solicitation #, trigram name, location, client). Does NOT judge fit — that's `fit-assessment.ts`.

### Company context + fit assessment — `src/lib/ai/company-context.ts`, `fit-assessment.ts`
- `getCompanyContext()` builds one prompt-ready markdown block from `company_profile` + active certs (identity, capabilities, bonding, **pursuit profile**: target sectors, project-size range, geographies, delivery/contract vehicles, differentiators, disqualifiers, past performance). Single source of truth — the agent and fit assessment both use it, so they judge against the same picture. Returns `hasPursuitProfile` so callers know when the profile is too thin to judge confidently.
- `assessFit(extraction, userId)` scores an opportunity against that context (Commercial/Operational/Financial/Compliance lenses) and returns `{recommendation: pursue|consider|pass, fit_score, summary, strengths, concerns, gaps, key_questions, profile_incomplete}`. Wired into `api/proposals/intake` (non-fatal) and surfaced as a card in `ProposalIntakeWizard`. **Quality scales with how completely the pursuit profile is filled in on `/company`.**

## 8. SECURITY / COMPLIANCE

- Middleware (`middleware.ts`) gates every route: unauthenticated users are redirected to `/login`. Public exceptions: login/auth, the risk-scores cron, and the Microsoft OAuth callback.
- **RLS is defense-in-depth, not the active boundary.** App traffic — including ~33 server pages — uses the service-role admin client (`lib/supabase/admin.ts`), which bypasses RLS. The auth boundary is the middleware. This is an accepted trade-off for a 2-user internal tool; if the team grows or sensitive data lands, move pages to the RLS-respecting server client (`lib/supabase/server.ts`).
- **A project may be marked `confidential` (2026-09-30), which demands a TOTP step-up to open and keeps it out of every aggregate and every outbound channel.** TOTP is served by the LOCAL gotrue container — nothing leaves the box, and there is no shared secret in the system. Only an **admin** can hold a step-up, deliberately including over an explicit `access_grant`. **Enrol at `/settings/security` BEFORE protecting a project**, or the only way back in is to clear `step_up_sessions`/`confidential` by hand in psql. ⚠ This is NOT a compliance control: the CUI rule below is unchanged, and a 6-digit code is not CMMC L2.
- `documents.classification` flags standard vs sensitive. All AI calls logged to `ai_queries`.
- US-only infrastructure. **Do not store CUI** until a GovCloud migration is done. GovCloud trigger: annual DoD revenue > $2M OR a contract requiring CMMC L2. Stack is portable by design (standard Postgres, no vendor lock-in).

⚠ **ADDING A RULE: the full version goes in that file, only the claim comes

### Postgres / PostgREST
- **`.or()` takes a LOGIC TREE, not a list of values.** An unescaped comma kills the query and callers swallow it into "no results"; unquoted parentheses return an EMPTY SET with no error. Build every such filter through `orIlike`/`orIlikeAnyWord`. Quoting is the defence, stripping is not.
- **Never `::` cast inside a PostgREST filter** — `.or()` rejects it, `.filter()` silently drops it. Use `->>` / `->`.
- **`.neq()` is NULL, and therefore not true, for a NULL column**, so a nullable status hides rows from every reader that filters on it.
- **A VALUE OUTSIDE AN ENUM FAILS THE WHOLE QUERY, NOT THE ROW** — `22P02` and a NULL row set. True of writes as well as filters, so one plausible-but-wrong value discards every other field in the same UPDATE. Check the members first.
- **`unique (a, b, c)` WHERE ONE COLUMN IS ALWAYS NULL ENFORCES NOTHING.** The shared-children convention (§4) manufactures this shape; use `unique nulls not distinct`.
- **`ON CONFLICT` cannot use a partial unique index, or an expression index.** For an expression, add a generated stored column and constrain that.
- **A table created by a migration applied as anything but `postgres` gets NO API GRANTS** — every call answers `42501`. If a feature "does nothing", check `role_table_grants` before reading its code.
- **PostgREST truncates at 1000 rows, silently.** Paginate anything that could exceed it. ⚠ **The ROW cap and the URL cap are two limits one constant cannot serve** — a filter rides in the query string, so `.in()` with 1000 uuids is a 37KB GET and Kong refuses it (`URI too long`). Chunk ids (~200) apart from rows, and never read a failed record read as "no records exist".
- **A field the caller never mentioned must be OMITTED, not nulled** — an explicit NULL does not fall back to the column DEFAULT. Two "Add…" buttons had never once worked. Conversely a multi-row insert needs a uniform column list.
- **Adding a discriminator means checking for a CHECK on it, and the columns it governs must travel together on every partial write.** Name the group.
- **A CHECK IS A LIST BAKED INTO THE SCHEMA; AN FK POINTS AT ROWS.** If the value set grows with the business it is a table — with `on update cascade` and no delete rule.
- **Write jsonb with `JsonIn`, never `Json`:** `Json` includes null and a NOT NULL jsonb column does not.
- **A HAND-WRITTEN TYPE STANDING IN FOR A GENERATED ONE DRIFTS SILENTLY.** Derive from the schema and `Refine` only what you deliberately narrow; where an interface must stay, make it `AssertNever` so the build names the drifted column.
- **An exclusion must be applied in SQL, BEFORE the `LIMIT`** — never in the caller afterwards, or withheld rows at the top return an empty answer.
- **A record that carries facts of its own must not hang off something rebuilt more often than it is.** Ask what the child OUTLIVES before choosing its parent.
- **`create or replace` DOES NOT REPLACE a function whose signature changed — it OVERLOADS it**, and a wrapper's retry path can then fall back to the version without your new filter, failing OPEN. Drop the old signature in the same migration.
- **`pg_stat_user_tables.n_live_tup` IS A STALE ESTIMATE** — it reported 1 against a real 15. Use `count(*)`.

### Google Workspace
- **Never assert one specific Google env var in a health check** — `getAccessToken()` picks a mode by which vars are set. Use `isGoogleConfigured()`.
- **Gmail meters by cost-units-per-MINUTE, not per request.** Pace bulk reads (~150–250ms).
- **The deal mailboxes (`moose@`/`tuaone@`) are read-only by design**; only `info@` holds `gmail.modify`. A 403 there is the scope tiering working.
- **A VENDOR'S FOLDER NAME IS A UI STRING, NOT AN API CONTRACT.** Google renamed the Meet folder and the import reported success 192 times against a Drive that had one. Match a LIST of names and say what you looked for.
- **Google's `/revoke` kills the whole GRANT, not one token**, so there is no such thing as rotating a refresh token here — re-consent IS the rotation. Revoke only to end access entirely.
- **Any token-file swap needs `launchctl kickstart`** — the OAuth store is cached in module scope.
- **Never duplicate the scope list**, and adding a scope does nothing to already-minted tokens; they 403 on first use.

### Next.js / React
- **Helpers shared between server pages and client components live in `src/lib`** — never exported from a `'use client'` file, or calling one from a server page throws at REQUEST time and neither `tsc` nor the build catches it.
- **A `loading.tsx` at a route group's ROOT 500s the whole route**, and a build that exits 0 having listed the route is not evidence it answers. In a subsegment it is fine and necessary.
- **A LAYOUT IS NOT A DATA BOUNDARY** — a layout and its page render in parallel. Gate in `middleware.ts` with `rewrite`, and the gate's destination must be a SIBLING of `[id]`.
- **Never use `request.nextUrl.origin` for user-facing URLs** — behind `tailscale serve` the Host header is localhost. Use `publicOrigin(request.headers)`.
- **`next dev` does not load the root `middleware.ts`** — auth and role behaviour must be tested against `next build` + `next start`.
- **A NEW CRON ROUTE IS UNREACHABLE UNTIL `middleware.ts` NAMES IT.** It typechecks, builds, registers, then 401s at its scheduled hour. Tell the two apart by which word comes back: the gate says `Not authenticated`, the route says `Unauthorized`.
- **Focus is `focus-visible:`, never `focus:`** — the latter fires on mouse clicks too.
- **Agent tools never fetch the app's own HTTP routes** — extract the shared logic into `src/lib`.

### Studio / infrastructure
- **A PROXY BEING TAILNET-ONLY SAYS NOTHING ABOUT THE PORTS UNDERNEATH IT.** `tailscale serve` was bound correctly while Postgres, the Supabase gateway, the app and LM Studio all listened on `*` and answered on the LAN — under the middleware that §8 calls the auth boundary. Three different layers held the fix and none of them is in this repo. ⚠ **Narrow the HOST side of the forward, never the container:** binding a container to 127.0.0.1 inside the Colima guest stops lima forwarding it at all and takes the platform down. Assert the listeners on every deploy.
- **The Tailscale serve config is Tailscale's state, not ours.** Assert BOTH listeners on every deploy (`deploy/tailnet-setup.sh`); losing them takes the platform down while every local check reports healthy.
- **Changing tailnet changes the MagicDNS suffix, and `NEXT_PUBLIC_*` is baked in at BUILD time** — a tailnet move needs `--fix` then a full rebuild, never a restart.
- **A pipeline's exit status is the LAST command's**, so `npm run build | grep … && launchctl kickstart` restarts on a FAILED build — and took production down once. Capture `$?` from an UNPIPED build, then grep the log. The same trap inverted: `launchctl list | grep -q` SIGPIPEs the producer and reports false; capture to a variable first.
- **The deploy runbook builds the WORKING TREE, not `HEAD`**, so a commit that does not compile ships green. After committing a rename, verify the COMMIT builds.
- **`next start` loads the build at boot** — a rebuild without `launchctl kickstart` changes nothing.
- **Work fired off after a route handler returns dies with the next kickstart**, and a deploy IS a kickstart. Store what the pass needs to resume.
- **Do NOT edit a shell script while it is running** — zsh reads by byte offset and dies with a syntax error that is not there.
- **`supabase db push --linked` targets the WRONG database.** Apply migrations by piping SQL to `docker exec supabase-db psql` AS `postgres`.
- **To patch an existing plpgsql function, derive it from `pg_get_functiondef` and edit it programmatically — never retype it.** `log_activity()` is 148 lines of per-table branches. Note it emits no trailing semicolon.
- **A backup is not a backup until it has been read back**, and its filename needs seconds.

### LM Studio / the local models
- **Check `lms ps` against the documented config before blaming code** for slow or stalled AI; an update resets it. The tell is a model id ending `:2` — a second 22GB copy resident. ⚠ **But `lms ps` can only see copies LM Studio OWNS** — a backend whose parent died is reparented to `ppid 1` and keeps its weights, so an ORPHAN presents as nothing at all: 19.70GB held for 3 days beside the live server, 39.4GB on a 36GB box, every check green. Test by PARENTAGE (`ps -Ao pid,ppid,comm`), not by version.
- **LM Studio serves ONE request at a time.** Overlapping crons queue behind each other, and a latency measured while a cron runs is measuring the queue.
- **`lmstudio-check.sh --fix` does NOT load a missing embedder, the one failure it cannot repair and the worst to have** — retrieval returns nothing while chat keeps answering, so Ber AI says "I found no correspondence" rather than erroring.
- **Never run OCR and the LLM at the same time, and unload the chat model before any re-embed or backfill.** `lms unload` drops wired memory 25.4GB → 4.3GB.
- **A chat model is swappable and an embedding model is not.** Nothing is fine-tuned, so a better `LOCAL_AI_MODEL` is an env change; changing the embedding model OR its width invalidates every row in `chunks` AND `thread_chunks` at once.
- **Ask `lms load --estimate-only` whether the box can hold more context** — hand arithmetic from GGUF metadata overstated it by more than double.

### Security & containment
- **Containment and access are different questions, and only one can be unlocked.** Anything that LEAVES the box can never be unlocked after the fact, so those paths take the absolute answer with no opt-out. Make the parameter explicit so a job that forgets gets the SAFE behaviour.
- **A security filter belongs at the choke point as a DEFAULT, not as a parameter every caller passes.** Forgetting to opt in costs a few results; forgetting to opt out costs the secret — and the default covers the route added next year.
- **Withholding from a model means handing it the COUNT of what was withheld**, and the count cannot be derived after the filter (`rows.length - visible.length` is structurally zero once the exclusion ran in SQL). **That count must carry the list's own predicates**, and the TOTALS above a filtered list are part of the list.
- **A nullable pointer added to a table filtered by a DIFFERENT pointer breaks an existing security filter without touching it.** When a table gains a second way to name its record, grep every reader that filters on the first.
- **A COUNT IS AN AGGREGATE, AND A ROW-FILTER HAS NO EQUIVALENT ON ONE.** A `head: true` count never receives rows, so `dropHidden()` cannot run and the exclusion is simply absent — a protected project reached the sidebar badge on every page. Filter in SQL, and `not.in` is NULL for a nullable column: use `or(col.is.null,col.not.in.(…))`, matching `dropHidden` exactly. Prove it on real rows — a malformed `.or()` returns an EMPTY SET with no error.
- **A link in an email is fetched by things that are not the reader** — Gmail prefetches and mail gateways follow every URL. Render a confirmation on GET, act only on the POST.
- **User-initiated mutations on tracked tables use `actorAdminClient()`**, or the activity log says "system".
- **`matchesPrefix` is NOT method-aware** — allowlisting a read path grants every mutation under it.

### Retrieval & the agent
- **An agentic loop must end on an answer, which means the last round carries no tools.** Falling out of the bottom shipped the NARRATION as the answer.
- **The KV prefix cache is why a round is normally fast, and shrinking the conversation is what throws it away** (3.2s vs 68.3s cold — 21x). Append; do not rewrite.
- **`fetch` has a 300s ceiling on prompt processing that no option in this codebase can reach** — undici's `headersTimeout` AND `bodyTimeout`, neither touched by `AbortSignal`. The chat stream goes over `node:http`, which applies no such timeout.
- **A timeout serving two different waits is set wrong for both.** Wait generously for the FIRST token (it grows with the conversation), keep the gap between tokens tight.
- **A truncating reader with no continuation parameter is not a reader**, and "no text" must say WHY — permanent (a scan) reads differently from transient.
- **A NULL `ai_summary` is a document the agent never opens**, because `list_documents` presents a document BY its summary. A text pass is not finished until the summaries follow.
- **A keyword search that only matches the whole phrase answers "nothing" where it means "not adjacent".** Fall back to any-word and rank by how many words matched.
- **Never make the model count rows — print the count.** Handed a 69-row schedule it answered 62.
- **A taxonomy written into a prompt is a second schema and it drifts silently**, because a category the model was never told about simply never fires. Generate the enumeration from the same rows the column references; keep it out of tool declarations especially.
- **A noise filter must be measured against the corpus, and every clever version costs evidence.** Share-of-prose withheld 11% including real bid invitations; density of ordinary words withheld 2.2% with none. Scrub the passage, do not withhold it.
- **A prompt example is training data, and a stale one is a lie the model repeats with confidence.** Never illustrate a rule with a limitation you are removing.
- **A money figure must carry its SHAPE** — annual, contract, one-time, asset and capture are five quantities, never interchangeable. A rolled-up sum with nothing in it is NULL, not 0.
- **`fit_score` carries ±20 points of sampling noise.** Read the verdict, never the number.

### Matching & extraction
- **Ambiguity must mean NO match**, and one match is not a unique match — it is an unchallenged one. A lone hit on a weak key resolved "Cliff" to an unrelated academic on a live deal. ⚠ **But a two-signal bar makes a record INVISIBLE where one signal is structurally unavailable for the source** — a document has no participants, so a one-word project name could never match and 38 deal documents sat as company knowledge with no proposal. Do not weaken the bar; assert an alias. When a matcher serves a new KIND of source, enumerate the signals that source can never carry. ⚠ **And a CONTAINER a human filed into — a folder name — is an assertion, not a description**, so it resolves deterministically (`resolveMeetingTarget`) and writes a `linked` link, never going through the fuzzy matcher at all.
- **A fuzzy threshold is measured against the real corpus, never chosen** — and an AUTOMATIC bar and a PRE-TICK bar are two bars, never one number. A threshold that is a share of the corpus gets looser the less it reads. **Two identically shaped names fall either side of any number you pick:** `"Riverdale Site"` → *Riverdale — Cleveland-Cliffs (IL)* is 0.30303 and `"Steelton Site"` → *Steelton — Cleveland-Cliffs (PA)* is 0.290323, so at 0.3 one matched and the other returned NO candidates. Lowering it moves the cliff; WHICH word matched is the signal.
- **A SHARED INDUSTRY WORD IS THE ONE THING AN IDENTIFIER MUST NOT BE** — it put Bloom Energy's logo on `bfaenergy.com`, and counting matched tokens let a hospital/airport project claim a 664-message family thread. Require the whole name or one token rare in the corpus; keep PLACE names out of the stopword list, but **a COMPASS DIRECTION is a qualifier and not a place** — three "West Virginia" sites resolved to *West Wendover* on the word *west*. **So is an ABBREVIATION of a word already on the list, and so is a COLOUR:** `building` was stopworded and `bldg` was not, so *Bldg 1520* matched *Bldg. 4140* on a different base; *Golden Rock* and the DoD *Golden Dome* programme both took *Alaska Golden Summit*. Add the word, then prove nothing was lost — that record is still reached on *summit*.
- **A mailbox is a better key than a name** — and check what the field MEANS on each side, or resolving `side='them'` says someone owes themselves.
- **A DETAIL FOUND IN A THREAD BELONGS TO THE MESSAGE IT WAS IN, NOT TO THE THREAD.** A rendered thread puts a `To:` line under every heading, so a signature's phone at the foot of one message is nearer the NEXT message's recipient than its own sender — which offered Eric's own cell as the number for four counterparties and spread one number across three people. Split on the message headings and attribute only to the SENDER. Then: a value two people claim goes to the one with strictly more sightings and the other gets nothing, and a value belonging to one of OURS is never written onto a counterparty — that leak is a NUMBER, not an address, so an address allowlist cannot see it.
- **A HUMAN NAME HAS STRUCTURE A SIMILARITY SCORE THROWS AWAY.** The name on a phone is not the name in the CRM (`Eric Tuaone` vs `Ericson Tua'one`, 0.473 and meaningless): delete punctuation rather than split on it, require the surname WHOLE, allow a first name only as a prefix of something longer, and never accept a prefix alone. And **a person-shaped field a model filled holds organizations** — our own company "attended" four of its own calls — so decide on the `is_organization` flag, never on the name — ⚠ **but the model's flag may CONVICT and never ACQUIT**: reading it with `??` and falling back to a name test only when absent let `is_organization: false` silently disable the rule, and three companies were about to be created as people. Make the tests additive, and where there is no flag at all, SKIP rather than guess.
- **Never print a reader's own name back at them.** When the owner IS the reader, "this one is yours" is the information.
- **A matcher must never learn from its own matches**, and a self-loop guard keyed on a DISPLAY NAME is defeated by a rename that is itself a good idea — 27% of the commitment ledger turned out to be Pepper reading her own notes. Key the guard on the ADDRESS, which is structural.
- **A new record type is a destination for the HUMAN, never a classification for the model.** The model has no sight of the database — so **its `kind` is a guess and a match is a fact.** Seeding a target from the model's kind and the matcher's id sent an opportunity's uuid to the projects branch; carry the kind the MATCH came from.
- **A substring hint matches any word that CONTAINS it** — `title` is inside `Entitlements`, which silently killed every land/title filing rule. Assert each rule's hints name at most one candidate. ⚠ Same bite in a convention check: `(?:bg|text)-\$\{` matched `pepper-text-${Date.now()}`, a filename. The prefix must START a token.
- **A file type with no branch is invisible, not unreadable — and nothing reports it.** A missing pptx branch left two investor decks with no `documents` row at all. Count the REASON beside the number; an unlabelled count is not a coverage signal.
- **A liveness check needs a CLOCK, not a count** — a count that has stopped growing is indistinguishable from a quiet inbox, and a check on the PRODUCING half of a loop reads green while the consuming half has never run.
- **Read `documents` with `superseded_at is null`** or the graveyard reads as a gap.
- **Two sources for one figure get two COLUMNS, not a winner.** On a rezone, the fact that anyone disagreed is the fact worth keeping.
- **A file name is not evidence of sameness, and neither is size** — hash the bytes, and write the hash at EVERY door. The mirror: identical bytes are not the same document when the name carries the only distinction (four blank MNDAs for four counterparties). **And an ID is not evidence of DIFFERENCE** — one meeting arrived under two Google event ids and every consumer doubled it. Dedupe a vendor's feed on what the thing IS, at the choke point, merging the duplicates' children.

### Shape of a pass
- **Filling a blank and overwriting a value are different acts, and only one is safe to automate.** ⚠ And whether a source DESCRIBES its subject is a property of the source's SCOPE, so one function fed by a record-scoped and a corpus-wide source needs a `fillOnly` parameter, not a policy: **the broad source fills, the narrow source decides.** ⚠ And WHICH act is safe turns on whether the source DESCRIBES the field's subject or only MENTIONS it: one thread covering Steelton, Riverdale and Weirton links to all three, so newest-wins rewrote each one's own address to "Steelton, Riverdale, Weirton". A title off a person's signature describes them (overwrite); a deal's location in a three-deal thread is incidental (fill only). ⚠ **The same test governs a whole ENTRY, not only a field:** 9 of 10 recorded calls name 2–8 deals, and writing the one narrative to each put the Steelton negotiation on Riverdale's feed. Ask the extraction for what it said about THAT deal, and for null when the deal was merely named. ⚠ **And a per-LINK pass fans out across links:** a thread correctly filed onto three deals had every attachment copied to all three, and a per-record dedupe cannot see it. Ask each FILE which of the thread's records it names — and keep "none or all of them" meaning all of them.
- **Two doors for one artifact means asking which one OWNS its index, or both build one** — the same text in two corpora is two answers that can disagree. Separate custody from search; and where the deferring path cannot know whether the other succeeded, reconcile afterwards with "index it anyway" as the fallback. Presence in the other corpus is not COVERAGE — the caps differ, so compare character counts.
- **Never fork a shared pass — add a target.** The one forked copy of `runDocumentAiPass` silently discarded 413,000 characters. The mirror: a pass over a table shared by several KINDS must filter the kind column.
- **An automatic producer must write the same table the manual one does**, or every reader sees only the hand-typed half. Ask which table the READERS select from.
- **A pass that reports what it did must read before it writes, or it claims work it did not do.** Pair every fill-not-overwrite pass with a script that calls it TWICE and asserts the second run reports nothing.
- **A destination that does not carry what creating carries reads as losing the work.** If two paths differ only in WHERE the work lands, they are one pass with a target parameter.
- **A record created with no owner is invisible under a default "mine" scope**, and a promotion must carry everything the record's next button needs.
- **A provenance line that invents a provenance is worse than no line** — every arm of it must be true for every source. **When a function branches on where something came from, every source that can reach it needs an arm, not just the one being added today**: the fix for texts left notes stamped "Email — Call with …", one source late.
- **A cleanup that is a side effect of having work to do never reaches the rows with no work.** Ten `thread_links` to a deleted project were caught up and attachment-free, so the drop inside the apply loop never examined them — immortal and invisible for five weeks. A polymorphic pointer needs its own reaper, run unconditionally. ⚠ Same bite in a PROJECTION: every recording sweep writes its `meetings` row last (the recap is a model pass), so `applyThreadUpdates` had nothing to move, and a link caught up on text AND attachments is never visited again — both voice memos on the box sat `unfiled` under a correctly `linked` thread. Ask from the side that just changed.
- **An orphaned projection looks perfectly live, and renaming or splitting its source is what orphans it.** Build the "still live" set from what SHOULD publish, not from what succeeded this run. **A projection of a record that MOVES goes stale the same way** — reconcile its FIELDS, not just its membership.
- **A COLUMN THAT STILL EXISTS BUT HOLDS NOTHING READS AS AN EMPTY ANSWER**, and a sentinel default then dates the whole corpus to 1970: Apple keeps a note's creation time in `ZCREATIONDATE3` and `…DATE1` is null for all 353. Verify one row against something you know, and never fall back to a value a reader cannot tell from a real one.
- **A verification script whose `finally` calls `process.exit` swallows the throw it is unwinding.** And when a check fails, suspect the check.
- **MEASURE BEFORE BUILDING, AND MEASURE THE DATA'S SHAPE RATHER THAN ITS SIZE.** Repeatedly the premise was wrong: the Drive was already clean, three planned passes were built and then removed, deal records turned out to be clean while the rolodex was the mess, and a "stale proposals" purge would have retired live deals. Absence of a flag is not a withheld answer.

### UI
- **ONE QUANTITY, ONE DEFINITION, or the reader trusts none of them.** Three "needs attention" numbers on one screen were 1, 99+ and 197. Two different quantities must be named apart and never summed; a badge cap invents a third. A label written inline on four screens is a label with no owner.
- **A bare em dash at a value's own weight reads as a failed render.** Omit the row, or name the absence in words.
- **When every row is red, red has stopped signifying.** Band it, and reserve the colour for what is still actionable.
- **A control that only appears on hover does not exist on a phone**, and one without `focus-visible:opacity-100` is invisible to a keyboard user.
- **A SURFACE HIDDEN BECAUSE IT IS EMPTY IS HIDDEN EXACTLY WHEN SOMEONE NEEDS TO FILL IT.** Count-gating is right for READING a populated record and wrong for the first WRITE: 17 of 19 projects had no meeting, so the only door to logging one sat under "More". Gate for reading; put creating where no count can reach it. And a deep link that promises an open form must be asserted against the pages that actually read the param — a href is a string, so `tsc` sees neither half.
- **A cache in `localStorage` for content that lives in the database is not a cache, it is the only copy the page can see.** Read the stored copy server-side; let the refresh only improve on it.
- **Check whether the data is already on the row before calling a list "an extraction problem".** `/decide` looked like schema work and was a UI change.
- **Fixing a generator changes nothing the reader sees** — the old rows carry the old text. Back them up, then rewrite them.
- **A parent record's value is the sum of its leaves and never its own figure as well**, and parenthood is judged by what is PRESENT in the same set.
- **A shared renderer wired to one surface is worse than no shared renderer.** Grep for a renderer before building one, and for every surface that should call it after. `resolveMeetingTarget` answered the record-matching question properly for a meeting's TITLE while the deals a meeting NAMED still went through a trigram threshold — 5 of 52 matched, against 20 through the resolver, with a duplicate stopword list drifting beside it. ⚠ **And the THIRD surface was the email queue, where a CONSUMER had been written for a producer that never existed:** `resolveMergeTarget` read `opportunity_name` off a candidate the projects-only matcher could not produce, so no opportunity was ever a merge target — and a model that cannot NAME the record proposes a new one. 110 of 126 staged sessions proposed CREATING a record against a register of 26. **Grep for every other surface asking the same question, and check whether something already consumes the answer you are about to start producing.**
- **A hand-written enumeration beside a registry drifts, and a ⚠ comment saying so does not stop the SIBLING drifting — or the next COMPONENT.** `/decide` fixed exactly this in its count map and left the chip row spelled out, so a new kind got a count and no chip; the Documents tab then did it again, its `DOC_TYPES` array carrying a comment about having already drifted once while still missing six types — 163 documents its own type filter could not filter for. Derive every kind-keyed structure from the registry; make its declaration order the reading order. **Where there is no registry (`doc_type` has no CHECK and several writers), the ROWS are the registry** — derive the filter from the values present, and keep a curated list only for what a human picks from.
- **An untyped string event is a contract nothing checks, and it hides a duplicate of itself.** Four docks opened via `dispatchEvent(new Event('open-…'))` from 8 sites; a rename silently stops opening one and `tsc` cannot see it. Typed registry + a dispatch helper, and check BOTH directions. ⚠ A check matching `new Event(` only missed the two `new CustomEvent(` sites — one of which kept its own second copy of the name.
- **`cn()` is tailwind-merge, so two classes in the SAME utility group do not compose — the later one silently deletes the earlier.** An urgency tint and a cursor highlight were both `bg-*`, so the most urgent row lost its colour exactly when you navigated onto it. `tsc` passes, the build passes, both classes are in the source. Two signals that must show at once go in DIFFERENT groups — a ring, a border, a child.
- **A sticky element inside a PADDED scroll container needs the padding bled back out** (`-mx-5 sm:-mx-6 px-5 sm:px-6` + an opaque background), or the canvas shows through beside it. Anything sticking below it must clear it — put the bar's height in a token both read.
- **WCAG contrast is the wrong instrument for SURFACE-vs-SURFACE separation — use OKLCH lightness delta.** The ratio's `+0.05` floor swamps real differences at the dark end: a rail at L 0.155 read 1.03:1 against an L 0.13 canvas and still read 1.031:1 at L 0.085. - **A density token moves HEIGHTS, not just gaps — and one of them is the 44px touch target.** `h-11` is `calc(var(--spacing) * 11)`: exactly 44px at the default, 38.7px once tightened, so 66 tap targets shrank below the floor in 32 files with nothing reporting it. - **A Tailwind class string stored in the database is never generated.** Store a tone NAME against a palette declared literally in source, and reject an unknown tone.
- **A nav item's `alsoMatches` may only name paths with no nav item of their own**, and a filter kept only in component state is not a view — put it in the URL.
- **New UI uses the Panel / Chip / `label-caps` idiom and `.elev-*`, never raw `shadow-*`.** Form controls come from `src/components/ui/field.tsx`; dates use `DatePicker`. No glassmorphism, colour only for status meaning.
