### AI Model Rules (CURRENT — FULLY LOCAL since 2026-07-07)

**The platform is fully self-hosted and fully local-AI as of the 2026-07-07 cutover** (Richard's decision: absolute security, nothing leaves his hardware). Production = the Mac Studio, tailnet-only: app at `https://richards-mac-studio.tail9acc02.ts.net/`, self-hosted Supabase at `:8443`, LM Studio on localhost:1234. **(The MagicDNS suffix changed `tail0e5306` → `tail9acc02` on 2026-09-16 when the tailnet moved to the berwilson.com Workspace org; the Studio is now `100.102.45.39`. Dated entries below still name the old values — that is history, not current state.)**

- **All runtime AI** → `qwen/qwen3.6-35b-a3b` via LM Studio's OpenAI-compatible API (`AI_PROVIDER=local`, `src/lib/ai/local.ts`). Expect ~30–60s on extraction-class tasks (reasoning-heavy model, ~75 tok/s generation).
- **LM Studio load configuration is load-bearing and resets on an eject/reload** — assert it with **`zsh deploy/lmstudio-check.sh`** (`--fix` reloads at the documented settings), which is now part of the deploy runbook. Found drifted to **173,824** on 2026-09-30, costing +1.38 GiB on a box down to 314MB free with 10.7 of 12GB swap in use, for a window the agent cannot reach (`AGENT_CONTEXT_BUDGET_CHARS` caps a conversation near 88k tokens). Settings (2026-09-26): `--ctx-size 131072` with `--cache-type-k q8_0 --cache-type-v q8_0` — the q8_0 cache is what pays for the doubled window, costing +2.12 GiB over 65,536 f16 rather than +5. `AGENT_CONTEXT_BUDGET_CHARS` and `AGENT_DOC_WINDOW_CHARS` in `.env.local` are sized to it and must move with it. **Check `lms ps` after any reload:** a model id ending `:2` means a SECOND 22GB copy is resident (41GB against 36GB of RAM — seen live), and `--parallel` reverts to 4 whatever it was set to.
- **Embeddings** → `text-embedding-qwen3-embedding-0.6b` at its **native 1024 dims**, stored in `vector(1024)` on BOTH `chunks` and `thread_chunks`. The width lives in ONE place — `EMBEDDING_DIMS` in `src/lib/ai/local.ts` — and must equal the schema; when they match, `localEmbedding` returns the model's vector untouched (the truncate+renormalize branch only runs if `EMBEDDING_DIMS` is deliberately made narrower). **Never mix embedding models OR widths** — either change means wipe + re-embed BOTH tables (`deploy/reembed.mjs`), never one of them. **A chat model, by contrast, is swappable at will**: nothing is fine-tuned, all knowledge is in Postgres, so a better `LOCAL_AI_MODEL` costs nothing to adopt.
- **Company knowledge base** → fed by the nightly Drive sync over `GOOGLE_DRIVE_KNOWLEDGE_FOLDER_ID` (142 of 154 live `is_company` documents; email attachments NEVER land here — `importThreadAttachments` returns 0 for any thread not linked to a project or opportunity). **`documents` AND `opportunity_documents`** both carry `excluded_at`/`excluded_reason` (a human's "not knowledge" — the ROW IS THE TOMBSTONE, §12) and `filing_confirmed_at` ("it is right where it is"); the second table got them 10-14, and until it did, a filing audit over both ran GREEN and reported all 103 of those documents clean, because PostgREST answered `42703` and the caller read `data` as null. **An opportunity's documents are their OWN TABLE** — `documents` has no `opportunity_id` — and `chunks` reaches them through `opportunity_document_id`, so a count on `document_id` returns 0 and zero reads as "never indexed". `refileDocument`/`excludeDocument`/`confirmDocumentFiling` in `src/lib/documents/refile.ts` take a `DocumentSource` that defaults to `documents`; re-filing re-points chunks and never re-embeds. **`composed_documents` (2026-10-22) is the job record for a document BER AI WROTE** — a shared child, `status` composing|ready|failed paired with `requested_at` because a kickstart leaves the first immortal, and `document_table` says which of the two documents tables its result landed in. The document is filed `embedding_status='skipped'` until a human confirms it, or the model retrieves its own draft back as evidence (§12). **Where a document BELONGS is asked in one place** — `matchDocument` in `src/lib/documents/match.ts`, serving the company-knowledge queue (`unfiled.ts`), the wrong-deal queue (`misfiled.ts`) and the mail sweep's per-attachment target.
- **Office files** → read directly, no model call: `.docx` via mammoth, `.xlsx` and `.pptx` via `fflate` over the OOXML (`src/lib/ai/document-text.ts`). pptx was added 2026-09-27 — before that `documentKind` had no branch for it and decks were skipped with no `documents` row created at all.
- **PDFs** → local text extraction via `unpdf` (no model call for transcription). **Scanned PDFs and images → Apple Vision OCR** (`bw-ocr`, `scripts/ocr/card-ocr.swift`), spawned like whisper.cpp: renders each page at 200 DPI and recognizes it. No model, no RAM held resident, nothing leaves the machine — the 11-page scanned Alaska mining lease read in **3 seconds**. **A vision LLM is deliberately NOT used and there is no room for one:** the box is 36GB, llama-server holds 19.7GB of weights plus 5GB of KV cache, Colima reserves 3GB, and swap already runs full. OCR is also simply better at dense printed text.
- **Web research / enrichment** (`research.ts`) → blocked in local mode unless `LOCAL_ALLOW_WEB_RESEARCH=true` (Gemini + Google Search). Currently ON for the Enrich Profile buttons. "Only the query leaves" was **prose and nothing else until 2026-10-11** — the arg went out verbatim, unchecked and unlogged, and `run_research` let the MODEL compose it. Now every outbound query passes `guardOutboundText` (`src/lib/security/egress.ts`, refuses a protected project's name, fails closed) and lands in `ai_queries`, refusals included.
- The Gemini path in `gemini.ts` survives behind `AI_PROVIDER` but only web research reaches it (`gemini-2.5-flash` + Google Search grounding in `research.ts`); its pre-cutover roles — extraction, classification, the agent loop, `gemini-embedding-001` at 768 dims — are history, see the log. Cloud Supabase project `qauclkrdejgtpywqixho` is **paused** (restorable safety net); the Vercel project is **deleted**.

Anthropic Claude is not used at runtime (removed 2026-06-22). **Every AI call logs to `ai_queries`** (user, prompt, response, model, tokens, latency) — keep that contract when adding calls.

## 4. DATABASE SCHEMA

**Source of truth is `src/types/database.ts`, and it covers every table** — 101 types over 100 live tables on 10-24, the extra being a view. ⚠ **COUNT IT, NEVER TRUST THE NUMBER HERE** (`gen-types` prints both and asserts they match): it read 97 four tables ago, and on 10-23 it was right for an hour before a concurrent session's migration made it wrong — two sessions share this repo. Regenerate with `npm run gen-types` (→ `deploy/gen-types.sh`), which reads `SUPABASE_DB_URL` or falls back to the running container, asserts it reached THIS database and covered every live table, and refuses to overwrite the file while it has uncommitted changes (two sessions share this repo). `-- --force` is the deliberate override.

**Row types come from the schema, not from hand.** Six modules carried 1,290 lines of hand-maintained row interfaces while gen-types was disabled; they are now aliases of the generated `Row`, with `Refine<T, R>` (in `src/lib/supabase/types.ts`) overriding only the jsonb/array columns a module narrows and the CHECK-backed unions the generator can only call `string`. `LeadRow` is the one interface still written out, because it is mostly per-field documentation — two `AssertNever` assertions make it unable to drift and name the column when it does. **Write jsonb with `JsonIn`, never `Json`:** `Json` includes null and a NOT NULL jsonb column does not. **Never add an `as never` cast** — there are zero, and this section has forbidden them all along. The untyped `createUntypedAdminClient()` survives for dynamic-table and embed-heavy reads the generated client cannot infer; the TYPES no longer depend on it.

Migrations live in `supabase/migrations/` numbered chronologically. ⚠ This line read "41 as of this writing" against **176** files — a hand-incremented count drifts silently, so `ls supabase/migrations/*.sql | wc -l` rather than trusting a number written here.

### Conventions (unchanged)
- All PKs: `id uuid default gen_random_uuid() primary key`.
- All timestamps: `timestamptz default now()`, UTC.
- RLS enabled on every table.
- `activity_log` is append-only — no UPDATE/DELETE policies, ever. **A DELETE therefore survives itself**: `log_activity()` writes `to_jsonb(old)` into `metadata`, so a hard-deleted row is recoverable from the log. The trigger also does a **generic column-by-column diff** for the narrow scalar tables in `_audited_in_full` inside the function — ⚠ COUNT IT there, not here. Gated to a list, because `documents`/`updates` carry hundreds of KB of text and diffing those would store both copies on every edit. ⚠ **And the trigger itself is applied table-by-table, so it is a hand-written enumeration that drifts** — 46 tables carry it and nine record-like ones still do not.
- `updated_at` auto-maintained by trigger; tracked tables auto-insert into `activity_log` via trigger.

## 5. AI ARCHITECTURE

### Unified Gemini client — `src/lib/ai/gemini.ts`
- `callGemini({ task, systemPrompt, userMessage, userId, promptVersion?, maxTokens?, jsonMode? })` — text in, text/JSON out. `jsonMode` defaults true (uses `responseMimeType: application/json` + strips stray code fences).
- `callGeminiWithFile({ systemPrompt, prompt, file: { mimeType, dataBase64 }, userId, logLabel?, promptVersion?, maxTokens?, jsonMode? })` — multimodal: a PDF/image plus a text instruction. Used by document and certification summarization.
- Both return `{ data, model, tokensIn, tokensOut, latencyMs }` and log to `ai_queries` (fire-and-forget). When the model returns valid JSON, `data` is the parsed object; otherwise `data` is the raw string — callers should branch on `typeof data === 'object'`.

### Extraction shape
Extraction prompts return structured JSON (summary, action_items, waiting_on, risks, decisions, mentioned_parties, mentioned_projects, confidence). See `src/lib/ai/prompts/extraction.ts`.

### Agent — `src/lib/ai/agent.ts` + `agent-tools.ts`
Local-Qwen agentic loop, `AGENT_MAX_TOOL_ROUNDS` rounds (default 12, the last tool-free — §12). Injects the Ber Wilson company profile into context so the agent knows the company's qualifications without a tool call. Tools are declared in `agent-tools.ts` and executed via `executeToolCall`. Conversations persist to `agent_conversations` / `agent_messages`.

**Construction Executive Agent persona:** senior EVP/COO, 25+ yrs government contracting, large-scale development, design-build GC, prefab, construction finance. An owner-operator, not a consultant. Four lenses on every recommendation: **Commercial** (can we win it?), **Operational** (can we deliver it?), **Financial** (can we get paid, at what margin?), **Compliance** (can we protect the downside?). Response protocol: Situation → Risks → Recommendation → Next Decision. Never ungrounded guesses; never hide risk; never substitute for legal/tax counsel; always distinguish facts, estimates, and judgments.

### Hybrid retrieval (RAG)
Query → SQL filter → vector search (`match_chunks` RPC over `chunks.embedding`) → re-rank (recency/confidence/cosine) → top chunks into context → grounded answer with citations → log to `ai_queries`.

### Proposal matching — `src/lib/ai/proposal-matching.ts`
Dedupes an inbound opportunity against existing `projects`/`parties` (solicitation #, trigram name, location, client). Does NOT judge fit — that's `fit-assessment.ts`.

### Company context + fit assessment — `src/lib/ai/company-context.ts`, `fit-assessment.ts`
- `getCompanyContext()` builds one prompt-ready markdown block from `company_profile` + active certs (identity, capabilities, bonding, **pursuit profile**: target sectors, project-size range, geographies, delivery/contract vehicles, differentiators, disqualifiers, past performance). Single source of truth — the agent and fit assessment both use it, so they judge against the same picture. Returns `hasPursuitProfile` so callers know when the profile is too thin to judge confidently.
- `assessFit(extraction, userId)` scores an opportunity against that context (Commercial/Operational/Financial/Compliance lenses) and returns `{recommendation: pursue|consider|pass, fit_score, summary, strengths, concerns, gaps, key_questions, profile_incomplete}`. Wired into `api/proposals/intake` (non-fatal) and surfaced as a card in `ProposalIntakeWizard`. **Quality scales with how completely the pursuit profile is filled in on `/company`.**

## 6. PROPOSAL INTAKE (the intelligence on-ramp)

Already built, end to end:

2. `api/proposals/intake` — runs extraction + `proposal-matching` against the company profile, produces an assessment and a proposed set of projects/parties/entities.

## 7. CONVENTIONS

### Code
- TypeScript strict mode. **Zero `any` escapes as of 2026-07-12** (was ~115 → ~23 → 0); don't add any back. Jsonb inserts use `as unknown as Json`; enum filters cast to `Database['public']['Enums'][…]`; polymorphic JSX wrappers use `ElementType`.
- Server components default; `'use client'` only when interactive.
- All DB access via Supabase clients — no raw SQL in components.
- API routes handle AI + mutations; pages fetch via server components.
- Error boundary + `loading.tsx` on every route. *(Aspirational — measured 10-09: 61 `loading.tsx` and 52 `error.tsx` against 97 pages. Measured again 10-28: 74 `loading.tsx` and 55 `error.tsx` against 97 pages. ⚠ Never at a route group's ROOT — §12.)*
- **Form controls come from `src/components/ui/field.tsx`** (`Field`/`Input`/`Select`/`Textarea`/`FieldDate`/`FormSection`/`FormGrid`/`FormActions`), or at minimum from the class strings in `src/lib/utils/field-classes.ts`. Never a new local `inputClass`/`labelClass` — there were 29 of them. `Field` ties the label to the control via `useId`; pass an explicit `id` in a `<form action>` form, which submits by `name`.
- **Focus is `focus-visible:`, never `focus:`** — the latter fires on mouse clicks too. Follow `button.tsx`: `outline-none focus-visible:border-ring focus-visible:ring-3 focus-visible:ring-ring/50`.
- **Never print a stored enum at a reader** — `enumLabel(value, map?)` in `src/lib/utils/constants.ts`. Its humanising fallback matters: several of these columns are not controlled enums, so a map-only lookup renders blank.
- **Money is `formatValue` (abbreviated) or `formatMoney` (exact)**, both in `constants.ts`. No local copies; there were five.

### Naming
- Database: `snake_case`. TypeScript: `camelCase` vars/functions, `PascalCase` types/components.
- Files: `kebab-case` (non-components), `PascalCase` (components). API paths: `kebab-case`.

## 12. HARD-WON RULES

Each line is a bug that cost real hours, several of them twice. **The full
version of every rule — the story, the measurement, the date — is in
[`docs/HARD-WON-RULES.md`](docs/HARD-WON-RULES.md)** (254 rules on 10-29, counted not incremented; not
auto-loaded, grep it). What follows is the claim and the fix.

⚠ **BEFORE ADDING A RULE, read THE BAR FOR A NEW RULE at the end of this file**
and grep both files first — if an existing line covers it, extend that line.

### Postgres / PostgREST
- **`.or()` takes a LOGIC TREE, not a list of values.** An unescaped comma kills the query and callers swallow it into "no results"; unquoted parentheses return an EMPTY SET with no error. Build every such filter through `orIlike`/`orIlikeAnyWord`. Quoting is the defence, stripping is not.
- **A JSONB CONTAINMENT FILTER TAKES A JSON *STRING*; AN ARRAY BECOMES A POSTGRES ARRAY LITERAL.** `.contains(col, [{…}])` goes out as `{[object Object]}`, and the caller reports the failure as an ABSENCE. Assert the call shape.
- **Never `::` cast inside a PostgREST filter** — `.or()` rejects it, `.filter()` silently drops it. Use `->>` / `->`.
- **`.neq()` is NULL, and therefore not true, for a NULL column**, so a nullable status hides rows from every reader that filters on it. ⚠ **AND THE MIRROR RETURNS EVERYTHING AND LOOKS LIKE A RESULT:** `<>` against a value the column never holds is true for every row — `status <> 'completed'` on a column holding `open`/`done` reported 146 open against a real 41. Enumerate the distinct values first, and when a query disagrees with a rendered page reading the same table, suspect the QUERY.
- **A VALUE OUTSIDE AN ENUM FAILS THE WHOLE QUERY, NOT THE ROW** — `22P02` and a NULL row set. True of writes as well as filters, so one plausible-but-wrong value discards every other field in the same UPDATE. Check the members first.
- **`unique (a, b, c)` WHERE ONE COLUMN IS ALWAYS NULL ENFORCES NOTHING.** The shared-children convention (§4) manufactures this shape; use `unique nulls not distinct`.
- **`ON CONFLICT` cannot use a partial unique index, or an expression index.** For an expression, add a generated stored column and constrain that.
- **A table created by a migration applied as anything but `postgres` gets NO API GRANTS** — every call answers `42501`. If a feature "does nothing", check `role_table_grants` before reading its code. ⚠ **And the same blindness covers every OTHER per-table attribute applied table-by-table, because a trigger is a hand-written enumeration with no registry behind it.** `opportunities` carried no `log_activity()` while 40 siblings did, and `investors`/`investments` carried none while their cap-table counterparts did — so a hard delete left nothing in the append-only log §4 calls the undo. Twice in two days, both found by accident. LIST the tables that have such a trigger against the ones that should and compare the pair; never assume a table built later inherited it.
- **PostgREST truncates at 1000 rows, silently.** Paginate anything that could exceed it. ⚠ **The ROW cap and the URL cap are two limits one constant cannot serve** — a filter rides in the query string, so `.in()` with 1000 uuids is a 37KB GET and Kong refuses it (`URI too long`). Chunk ids (~200) apart from rows, and never read a failed record read as "no records exist".
- **A field the caller never mentioned must be OMITTED, not nulled** — an explicit NULL does not fall back to the column DEFAULT. ⚠ **BUT OMISSION ONLY WORKS WHERE A DEFAULT EXISTS:** `projects.sector` is NOT NULL with none, so omitting it is `23502` while its siblings `status` and `stage` are fine. Check for the default, and where a NOT NULL column has no honest value, REFUSE and say why rather than guessing a member of its enum. Two "Add…" buttons had never once worked. Conversely a multi-row insert needs a uniform column list.
- **Adding a discriminator means checking for a CHECK on it, and the columns it governs must travel together on every partial write.** Name the group. ⚠ **WHERE A CHECK ENUMERATES SCOPES, A NEW STATE NEEDS A NEW MEMBER, AND A FLAG THAT MERELY SATISFIES IT IS NOT ONE THAT MEANS IT** — reusing a purpose flag breaks the surface reading it. Drop/re-add the CHECK under one name; it has no `create or replace`.
- **A CHECK IS A LIST BAKED INTO THE SCHEMA; AN FK POINTS AT ROWS.** If the value set grows with the business it is a table — with `on update cascade` and no delete rule.
- **Write jsonb with `JsonIn`, never `Json`:** `Json` includes null and a NOT NULL jsonb column does not.
- **A HAND-WRITTEN TYPE STANDING IN FOR A GENERATED ONE DRIFTS SILENTLY.** Derive from the schema and `Refine` only what you deliberately narrow; where an interface must stay, make it `AssertNever` so the build names the drifted column.
- **A JUDGEMENT IS ONLY WORTH COMPUTING WHERE ITS QUESTION APPLIES, and a verdict on a decision already taken is noise that argues with the facts.** Gate such a pass on a FACT, never another model's guess — and check what CONSUMES a value before calling it dead.
- **An exclusion must be applied in SQL, BEFORE the `LIMIT`** — never in the caller afterwards, or withheld rows at the top return an empty answer.
- **A record that carries facts of its own must not hang off something rebuilt more often than it is.** Ask what the child OUTLIVES before choosing its parent.
- **`create or replace` DOES NOT REPLACE a function whose signature changed — it OVERLOADS it**, and a wrapper's retry path can then fall back to the version without your new filter, failing OPEN. Drop the old signature in the same migration.
- **A `.select()` COLUMN LIST IS A STRING, SO DROPPING A COLUMN BREAKS ITS READERS AND `tsc` SEES NOTHING** — a `42703` failing the WHOLE query on every document Ber AI writes, with typecheck, build and suite green. Same blindness behind `as unknown as`, which defeats the excess-property check. GREP the name; a green typecheck is not coverage.
- **`pg_stat_user_tables.n_live_tup` IS A STALE ESTIMATE** — it reported 1 against a real 15. Use `count(*)`.

- **AN ASSERTED ALIAS IS A FACT AND MUST REACH EVERY MATCHER, NOT JUST THE ONE IT WAS BUILT FOR** — twenty records' aliases steered THREAD routing and nothing else. Reuse the EXISTING alias rule (every token present as a whole token), and an alias claimed by two records makes BOTH unmatchable. Assert it, then MEASURE WHAT IT PULLED. ⚠ **AND AN ALIAS IS NOT STORED AS WRITTEN: `tokenize()` DROPS ≤2-CHAR TOKENS, SO `"Tensor CM"` IS STORED AS `tensor` — THE COUNTERPARTY.** Print what it tokenizes to; never act unattended on one whose stored form is shorter than its written one.

A transcript on the wrong record answers for it until somebody notices; one unfiled is still searchable. ⚠ Carry the human's string ON THE ROW — keeping it only on the intake session means dismissing that session ORPHANS the filing key. ⚠ And "belongs to no record" must be recordable, or every pass refuses it forever and that is indistinguishable from a backlog.

Three different layers held the fix and none of them is in this repo. ⚠ **Narrow the HOST side of the forward, never the container:** binding a container to 127.0.0.1 inside the Colima guest stops lima forwarding it at all and takes the platform down. ### Security & containment
- **Containment and access are different questions, and only one can be unlocked.** Anything that LEAVES the box can never be unlocked after the fact, so those paths take the absolute answer with no opt-out. Make the parameter explicit so a job that forgets gets the SAFE behaviour. ⚠ **AND A REFUSAL'S REASON IS WRITTEN FOR A LOG — REUSING IT IN THE MESSAGE THAT LEAVES IS HOW THE EXPLANATION OF CONTAINMENT BREAKS CONTAINMENT.** The guard names the protected project; the outbound body said so. Two strings: specific for the log, generic for anything that crosses. When a guard explains itself, ask who reads the explanation.
- **A security filter belongs at the choke point as a DEFAULT, not as a parameter every caller passes.** Forgetting to opt in costs a few results; forgetting to opt out costs the secret — and the default covers the route added next year. ⚠ **AND A ONE-TABLE CRUD ROUTE IS WHERE IT GOES MISSING** — of 61 route handlers touching one table with one write verb, **22 had no record check at all**, six of them siblings of a seventh that did. A PATCH carries only an id, so the parent must be READ before the write, which is precisely why it gets skipped. When several routes answer the same shape, the check belongs in the one spec they share (`src/lib/records/children.ts`, `src/lib/governance/registers.ts`) — and the parent columns must be absent from its field whitelist, or a body can re-parent the row onto a record it may write.
- **Withholding from a model means handing it the COUNT of what was withheld**, and the count cannot be derived after the filter (`rows.length - visible.length` is structurally zero once the exclusion ran in SQL). **That count must carry the list's own predicates**, and the TOTALS above a filtered list are part of the list.
- **A nullable pointer added to a table filtered by a DIFFERENT pointer breaks an existing security filter without touching it.** When a table gains a second way to name its record, grep every reader that filters on the first. ⚠ **AND IF THE WIDENED PREDICATE IS A `DELETE`, THAT IS DATA LOSS WITH NOTHING REPORTING IT.** Give it a positive discriminator, keep the `is null` arm for older rows, and prove it on a population that EXISTS.
- **A COUNT IS AN AGGREGATE, AND A ROW-FILTER HAS NO EQUIVALENT ON ONE.** A `head: true` count never receives rows, so `dropHidden()` cannot run and the exclusion is simply absent — a protected project reached the sidebar badge on every page. Filter in SQL, and `not.in` is NULL for a nullable column: use `or(col.is.null,col.not.in.(…))`, matching `dropHidden` exactly. Prove it on real rows — a malformed `.or()` returns an EMPTY SET with no error.
- **A link in an email is fetched by things that are not the reader** — Gmail prefetches and mail gateways follow every URL. Render a confirmation on GET, act only on the POST.
- **User-initiated mutations on tracked tables use `actorAdminClient()`**, or the activity log says "system" — so **making a table tracked means auditing every write path to it in the same change.** Adding `log_activity()` to `parties`/`entities` found FIVE of their eight mutating routes on the plain client; a trail whose every row reads "system" answers nothing, which is the only question it was added to answer.
- **`matchesPrefix` is NOT method-aware** — allowlisting a read path grants every mutation under it.

### Retrieval & the agent
- **An agentic loop must end on an answer, which means the last round carries no tools.** Falling out of the bottom shipped the NARRATION as the answer.
- **The KV prefix cache is why a round is normally fast, and shrinking the conversation is what throws it away** (3.2s vs 68.3s cold — 21x). Append; do not rewrite.
- **`fetch` has a 300s ceiling on prompt processing that no option in this codebase can reach** — undici's `headersTimeout` AND `bodyTimeout`, neither touched by `AbortSignal`. The chat stream goes over `node:http`, which applies no such timeout. ⚠ **The SAME ceiling hits a big UPLOAD from the other side**: a resumable PUT gets no response headers until the whole body is received, so a 1.6GB artifact at the measured 5.5MB/s (~291s) sits right on it. Chunk it — and `redirect: 'manual'`, because an intermediate chunk answers **308** and `fetch` follows 308 as a redirect, hiding the real status.
- **A timeout serving two different waits is set wrong for both.** Wait generously for the FIRST token (it grows with the conversation), keep the gap between tokens tight.
- **A truncating reader with no continuation parameter is not a reader**, and "no text" must say WHY — permanent (a scan) reads differently from transient.
- **A NULL `ai_summary` is a document the agent never opens**, because `list_documents` presents a document BY its summary. A text pass is not finished until the summaries follow.
- **A keyword search that only matches the whole phrase answers "nothing" where it means "not adjacent".** Fall back to any-word and rank by how many words matched.
- **Never make the model count rows — print the count.** Handed a 69-row schedule it answered 62.
- **A taxonomy written into a prompt is a second schema and it drifts silently**, because a category the model was never told about simply never fires. Generate the enumeration from the same rows the column references; keep it out of tool declarations especially. ⚠ **AND WHERE THE LIST IS HANDED OVER AT RUN TIME, ITS DISPLAY FORMATTING COMES BACK IN THE ANSWER** — shown `GridEdge (opportunity)` the model replied with exactly that at 0.95, and a correct whole-name resolver refused the right record. Put the tag where it cannot be read as the value, and strip your own decoration before giving up. ⚠ **A CURATED VOCABULARY ONLY A PICKER READS IS IN THE SAME POSITION AND LOOKS HEALTHIER** — 33 good role values sat in `constants.ts` read by two modals while five automated writers passed the model's prose through, so **1 of 104 rows conformed**. Ask which writers can reach the list; if any cannot, it is decoration.
- **A noise filter must be measured against the corpus, and every clever version costs evidence.** Share-of-prose withheld 11% including real bid invitations; density of ordinary words withheld 2.2% with none. Scrub the passage, do not withhold it. ⚠ **A GATE THAT READS PROSE CANNOT SEE THE ARTIFACT** — 65% withheld, every wrong reject a three-word body carrying 8–14 files. Widen on a FACT the source CARRIES, never a score.
- **A STRUCTURAL FACT HANDED TO A MODEL AS A HINT IS NOT RECORDED — it survives only if the model repeats it.** Calendar invitees were seeded into the extraction for the life of the feature, and a two-person meeting registered five attendees, one being our own company's row wearing a person's name. Assert the fact onto the row AFTER the model has spoken, at the shared choke point, on the strongest key it carries (an address, never a name).
- **A prompt example is training data, and a stale one is a lie the model repeats with confidence.** Never illustrate a rule with a limitation you are removing. ⚠ **AND AN EXAMPLE NAMING A REAL RECORD IS PRINTED AS A FACT** — Pepper's note quoted its own prompt as work she had done, in the line §11 relies on to report her unattended writes. Make every example a placeholder SHAPE; test that the prompt names no live record.
- **A money figure must carry its SHAPE** — annual, contract, one-time, asset and capture are five quantities, never interchangeable. A rolled-up sum with nothing in it is NULL, not 0.
- **`fit_score` carries ±20 points of sampling noise.** Read the verdict, never the number.

### Matching & extraction
- **Ambiguity must mean NO match**, and one match is not a unique match — it is an unchallenged one. A lone hit on a weak key resolved "Cliff" to an unrelated academic on a live deal. ⚠ **A two-signal bar makes a record INVISIBLE where one signal is structurally unavailable for the source** — do not weaken the bar, assert an alias, and enumerate what a new KIND of source can never carry. ⚠ **A REFUSAL must not be reported as an ABSENCE, because the caller creates on absence** — return `match | none | refused`; only `none` may create.
- **A fuzzy threshold is measured against the real corpus, never chosen** — and an AUTOMATIC bar and a PRE-TICK bar are two bars, never one number. **Two identically shaped names fall either side of any number you pick** (`"Riverdale Site"` 0.303, `"Steelton Site"` 0.290). Lowering it moves the cliff; WHICH word matched is the signal. ⚠ **A BORROWED BAR IS STILL A CHOSEN ONE** — measure it on the output it will judge, and make a hit hand back the candidates. ⚠ **THE OVERLAP COEFFICIENT MAKES A SHORT PHRASE A SUBSET OF EVERY LONGER ONE** — use Jaccard, and prefer FLAGGING a suspected duplicate to folding it.
- **WHEN A MATCHER CANNOT BE LOOSENED SAFELY, THE ANSWER IS A READER BEHIND A HUMAN PRESS, NOT A LOWER BAR.** Measure every record's distinguishing tokens against the real corpus first — `whiskey` is df 4, but `Eagle Mountain` reduces to `mountain` (281) and two Myton records BOTH to `myton`. Every threshold swept gave ~3 right in 28.
- **A SHARED INDUSTRY WORD IS THE ONE THING AN IDENTIFIER MUST NOT BE**, and counting matched tokens is not a bar. Require the whole name or one token rare in the corpus. Keep PLACE names out of the stopword list, but a COMPASS DIRECTION, a COLOUR and an ABBREVIATION of a word already on it are not places. ⚠ **"Every word must match" is the same test as "one shared word" once the stopwords are gone** (*Tensor Site* and *Tensor IQ Data Center* both reduce to `tensor`): 9 of 9 records a fuzzy gate would have created were wrong. ⚠ **And the vendor's own boilerplate is part of the haystack** — Gmail's *"eSigned Document **Ready**:"* convicted a template of being a *Power-**Ready** Site*. Require the WHOLE name contiguously and strip the wrapper first. ⚠ **A STOPWORD LIST IS NOT ENOUGH WHERE THE SHARED WORD IS A COUNTERPARTY: compute df over the RECORD NAMES and drop any token held by more than two.** `cleveland`/`cliffs` is shared by five records and outvoted the word naming the deal — two folders both scored 0.67 against the wrong one; scored on distinctive tokens, `steelton` (df 1) hit 1.0 on the right record and the ambiguous two correctly got NOTHING.
- **A mailbox is a better key than a name** — and check what the field MEANS on each side, or resolving `side='them'` says someone owes themselves.
- **A DETAIL FOUND IN A THREAD BELONGS TO THE MESSAGE IT WAS IN, NOT TO THE THREAD.** A rendered thread puts a `To:` line under every heading, so a signature's phone at the foot of one message is nearer the NEXT message's recipient than its own sender — which offered Eric's own cell as the number for four counterparties and spread one number across three people. Split on the message headings and attribute only to the SENDER. Then: a value two people claim goes to the one with strictly more sightings and the other gets nothing, and a value belonging to one of OURS is never written onto a counterparty — that leak is a NUMBER, not an address, so an address allowlist cannot see it.
- **A HUMAN NAME HAS STRUCTURE A SIMILARITY SCORE THROWS AWAY.** The name on a phone is not the name in the CRM (`Eric Tuaone` vs `Ericson Tua'one` scores 0.473 and means nothing): delete punctuation rather than split on it, require the surname WHOLE, allow a first name only as a prefix of something longer, never a prefix alone. And **a person-shaped field a model filled holds organizations** — our own company "attended" four of its own calls — so decide on the `is_organization` flag, never the name. ⚠ **But the model's flag may CONVICT and never ACQUIT:** reading it with `??` and falling back to a name test only when absent let `is_organization: false` silently disable the rule. Make the tests additive; with no flag at all, SKIP. ⚠ **A SURNAME IS A FAMILY, NOT A PERSON** — require the first name too (equal, or a prefix of something longer, floor of three). And on an IMPORT a false match SKIPS a row rather than merging two, which is invisible and which a dry run cannot find.
- **Never print a reader's own name back at them.** When the owner IS the reader, "this one is yours" is the information.
- **A matcher must never learn from its own matches**, and a self-loop guard keyed on a DISPLAY NAME is defeated by a rename that is itself a good idea — 27% of the commitment ledger turned out to be Pepper reading her own notes. Key the guard on the ADDRESS, which is structural. ⚠ **The same applies to PROSE THE MODEL WROTE: index it only once a human has confirmed it**, or next week the offer it drafted reads back as evidence about the deal.
- **GROUPED ROWS ARE JUDGED ON THE MERGED RECORD, or the verdict argues with the facts printed beside it** — judging the first sighting offered one of our own people as external, on a line whose company column named us. Merge first (fill, never overwrite; a convicting flag additive). ⚠ **AND A QUEUE WHOSE EVERY ROW GETS THE SAME BUTTONS HAS NOT CLASSIFIED ANYTHING** — let the class decide which actions exist, and enforce the refusal at the WRITE.
- **A new record type is a destination for the HUMAN, never a classification for the model.** The model has no sight of the database — so **its `kind` is a guess and a match is a fact.** Seeding a target from the model's kind and the matcher's id sent an opportunity's uuid to the projects branch; carry the kind the MATCH came from.
- **A substring hint matches any word that CONTAINS it** — `title` is inside `Entitlements`, which silently killed every land/title filing rule. Assert each rule's hints name at most one candidate. ⚠ Same bite in a convention check: `(?:bg|text)-\$\{` matched `pepper-text-${Date.now()}`, a filename. The prefix must START a token.
- **A file type with no branch is invisible, not unreadable — and nothing reports it.** A missing pptx branch left two investor decks with no `documents` row at all; `.doc` and `.eml` then did it again, hiding a Steelton PSA assignment and the Vistra base contract. Count the REASON beside the number; an unlabelled count is not a coverage signal. ⚠ **"correctly skipped" IS AN ASSERTION NOTHING CHECKED** — split it into kinds still unreadable, NAMED, and kinds readable now, which is a job to run.
- **A liveness check needs a CLOCK, not a count** — a count that stopped growing is indistinguishable from a quiet inbox, and a check on the PRODUCING half of a loop reads green while the consuming half has never run. ⚠ **A FILE's mtime is not its DATA's clock where the writer keeps a write-ahead log** (SQLite left the `.db` untouched and wrote to `-wal`, so the sweep cried "102h old" while transcribing a 90-minute-old memo): take the newest mtime across the set, because a check that cries wolf every run is one nobody reads on the day it is right. ⚠ **AND THIS RULE REACHED NEITHER PROBE** — a rule about how to read a KIND of thing means grepping every reader of it, into ONE helper. ⚠ **Same for an IN-PROGRESS status column**: a kickstart kills the writer before it records either verdict, so `running` is immortal and every reader must pair it with a started-at.
- **A CHANNEL WHOSE SETUP CANNOT BE AUTOMATED IS A CHANNEL THAT IS OFF, and nothing says so** — two hand-built Shortcuts were never built, so seven days of notes reached nobody while every run reported success. Assert DELIVERY, not configuration, and prefer the transport with no manual step. ⚠ **A CHANNEL HELD ON PURPOSE IS THE SAME HAZARD:** one default-deny table at the send choke point, the kind REQUIRED so `tsc` names every caller, the held set on the health page. Keep the schedule and gate the send — two switches that must agree is the drift.
- **Read `documents` with `superseded_at is null`** or the graveyard reads as a gap.
- **A FIGURE IN A DOCUMENT THE MODEL WROTE MUST APPEAR IN WHAT IT READ.** Gate money and percentages against the input set — the platform's figures, the evidence, and the human's own instruction, which is what makes the refusal recoverable rather than a dead end. Caught an invented `$20.0M` on the second live document, over a record whose evidence holds no 20 in any form. Scope it to money: gating dates, acreages and megawatts refuses honest work.
- **Two sources for one figure get two COLUMNS, not a winner.** On a rezone, the fact that anyone disagreed is the fact worth keeping.
- **A file name is not evidence of sameness, and neither is size** — hash the bytes, and write the hash at EVERY door. The mirror: identical bytes are not the same document when the name carries the only distinction (four blank MNDAs for four counterparties). **And an ID is not evidence of DIFFERENCE** — one meeting arrived under two Google event ids and every consumer doubled it. Dedupe a vendor's feed on what the thing IS, at the choke point, merging the duplicates' children.

### Shape of a pass
- **Filling a blank and overwriting a value are different acts, and only one is safe to automate** — WHICH turns on whether the source DESCRIBES the field's subject or only MENTIONS it. A title off a signature describes the person (overwrite); a deal's location in a thread covering three deals is incidental (fill only), and newest-wins rewrote each one's address to all three. ⚠ That is a property of the source's SCOPE, so one function fed by a record-scoped and a corpus-wide source needs a `fillOnly` parameter: **the broad source fills, the narrow source decides.** ⚠ **The same test governs a whole ENTRY** — 9 of 10 recorded calls name 2–8 deals, so one narrative written to each put the Steelton negotiation on Riverdale's feed. ⚠ **And a per-LINK pass fans out across links:** a thread filed onto three deals had every attachment copied to all three.
- **Two doors for one artifact means asking which one OWNS its index, or both build one** — the same text in two corpora is two answers that can disagree. Separate custody from search; and where the deferring path cannot know whether the other succeeded, reconcile afterwards with "index it anyway" as the fallback. Presence in the other corpus is not COVERAGE — the caps differ, so compare character counts.
- **TWO TOOL DECLARATIONS SHARING A NAME IS NOT AN ERROR ANYWHERE — THE EARLIER DISPATCH ARM SILENTLY WINS.** A new `search_correspondence` shadowed the SEMANTIC one the agent prompt directs the model to, on every turn, for three deployed hours, through a green typecheck, build and 824 tests. The miss was in what I grepped: the table, never the TOOL NAMES. Grep the vocabulary's NAMES, assert uniqueness in a test, and where the capability is real but the tool exists, **add a parameter to the shared tool**.
- **Never fork a shared pass — add a target.** The one forked copy of `runDocumentAiPass` silently discarded 413,000 characters. The mirror: a pass over a table shared by several KINDS must filter the kind column. ⚠ **A fork is hardest to see as two SIBLING MODULES written days apart, because neither looks like a copy** — the tell is a second module answering the same question for a second source, not a duplicated name. Diff the new source against the old before writing it.
- **A VERDICT COMPUTED BEFORE A FACT EXISTS MUST BE RE-ASKED ONCE THE FACT ARRIVES, AND FIXING THE PRODUCER DOES NOT FIX THE CONSUMER.** The router stopped gating on `relevance` in 09-22 and said why in a ⚠ comment; retrieval never did, so 48 asserted threads stayed unsearchable — two of them that comment's own evidence. Grep every reader of an overturned column, and gate the remedy on an identity, never a score.
- **A PREDICATE TRANSCRIBED INTO ITS READERS HAS A HOME PER READER, AND THE ONE THAT LIES TO YOU IS FOUND LAST** — a backfill printed `0 to index` immediately before indexing 48. One home they select from, then grep to prove there is no fifth.
- **A BIG NUMBER FROM A NEW EXTRACTOR IS NOT A RESULT UNTIL SOMEBODY READS THE TEXT** — 342,230 chars of `.eml` were mostly MIME scaffolding; recursing gave 7,571. Walk a container format recursively or not at all.
- **An automatic producer must write the same table the manual one does**, or every reader sees only the hand-typed half. Ask which table the READERS select from.
- **A pass that reports what it did must read before it writes, or it claims work it did not do.** Pair every fill-not-overwrite pass with a script that calls it TWICE and asserts the second run reports nothing. ⚠ **And a value normalized on READ must be normalized on WRITE, or the comparison can never converge** — a real invitee named `"Huge "` made one row rewrite itself on every run, because `parseAttendees` trims and the writer did not.
- **A destination that does not carry what creating carries reads as losing the work.** If two paths differ only in WHERE the work lands, they are one pass with a target parameter.
- **A record created with no owner is invisible under a default "mine" scope**, and a promotion must carry everything the record's next button needs.
- **A provenance line that invents a provenance is worse than no line** — every arm must be true for every source. **When a function branches on where something came from, every source that can reach it needs an arm, not just the one being added today.** A prefix discriminator is a registry with no type behind it, so **assert that every member agrees across every switch** rather than fixing them one failure at a time. ⚠ **AND A TRAILING `else` TURNS A MISSING ARM INTO A WRITE AGAINST ANOTHER TABLE'S ROUTE** — `/decide`'s accept chain tested two document kinds and a third fell through to the review route, so 120 rows answered `404`, green through typecheck, build and 802 tests. Make the branch DATA (a pure function returning `{method,url,body}`), walk every member × every action in a test, and refuse an unknown kind by name.
- **A cleanup that is a side effect of having work to do never reaches the rows with no work.** Ten `thread_links` to a deleted project were caught up and attachment-free, so the drop inside the apply loop never examined them — immortal and invisible for five weeks. A polymorphic pointer needs its own reaper, run unconditionally. ⚠ Same bite in a PROJECTION: every recording sweep writes its `meetings` row last (the recap is a model pass), so `applyThreadUpdates` had nothing to move, and a link caught up on text AND attachments is never visited again — both voice memos on the box sat `unfiled` under a correctly `linked` thread. Ask from the side that just changed.
- **An orphaned projection looks perfectly live, and renaming or splitting its source is what orphans it.** Build the "still live" set from what SHOULD publish, not from what succeeded this run. **A projection of a record that MOVES goes stale the same way** — reconcile its FIELDS, not just its membership.
- **A COLUMN THAT STILL EXISTS BUT HOLDS NOTHING READS AS AN EMPTY ANSWER**, and a sentinel default then dates the whole corpus to 1970: Apple keeps a note's creation time in `ZCREATIONDATE3` and `…DATE1` is null for all 353. Verify one row against something you know, and never fall back to a value a reader cannot tell from a real one.
- **A verification script whose `finally` calls `process.exit` swallows the throw it is unwinding.** And when a check fails, suspect the check. ⚠ **A script reading a TRUNCATED set is worse than none, because it is believed** — one went green over exactly 1000 rows (PostgREST's cap, which `.limit()` does not beat) against 1,203. **An empty population passes vacuously behind the same tick**: print what was examined. ⚠ **AND A CANARY MUST OUTLIVE WHAT IT GUARDS** — `gen-types` proved it had reached the Studio by asserting the schema held `project_spvs`; dropping that table made the check fail against the RIGHT database, naming a cause that was not the cause. Choose a sentinel the platform cannot lose.
- **AN ANCHORED PATTERN IS BLIND TO ITS OWN MARKER IN ANY OTHER POSITION.** `^(noreply|…)` let `drive-shares-dm-noreply@google.com` become a CONTACT. Test whole TOKENS — which also satisfies the mirror rule that a substring hint must start a token — and leave genuinely ambiguous words prefix-only. ⚠ **AND A FILE NAME'S SEPARATOR IS NOT A SPACE: `Steelton_PSA_Buyer_Redline.docx` matched neither `psa` nor `purchase agreement`**, because the rules padded short tokens with spaces to avoid matching inside a word. Split on every non-alphanumeric run and compare contiguous WORD SEQUENCES — which retires the padding entirely, and makes `Gypsa`≠`psa` and `Agenda`≠`nda` true by construction rather than by remembering.
- **A CORPUS WITH ITS OWN TRIAGE MUST NOT BE GUESSED INTO THE OTHER ONE'S RECORDS.** The clusterer excluded `pipeline='lead'`; the router did not, so 19 trade leads carried a deal link — a town's name inside *"needs Concrete Installation in Eagle Mountain, UT"*. ⚠ Gate the GUESS, never the fact: a promoted lead's derived link must survive.
- **A LINE THAT IS IDENTICAL FOR EVERY READER CANNOT JUSTIFY SENDING THEM THE MESSAGE.** It rides along on a message the reader's own work earned; it never opens the envelope — or two people get the same text every Monday until one of them acts. ⚠ And look for the opposite hole in the same pass: every per-person surface groups by assignee, so four of ten dated tasks, three already overdue, were invisible to every reader there was.
- **A PRODUCER'S GATE IS MEASURED BY THE HUMAN'S DISMISSAL RATE, NEVER BY ITS OWN CONFIDENCE** — 0.93 average while 93 of 95 `create` verdicts were wrong. Replay every candidate rule over the DECIDED corpus and take the LOOSEST that loses nothing. ⚠ A gated-out row is HELD, never dismissed, and the held count must be reported — a gate nobody can see is a black hole. ⚠ **AND A COUNT WITH NOTHING TO CLICK IS STILL ONE:** where the matcher places almost nothing, held rows need a PICKER, not a better matcher.
- **MEASURE BEFORE BUILDING, AND MEASURE THE DATA'S SHAPE RATHER THAN ITS SIZE.** Repeatedly the premise was wrong: the Drive was already clean, three planned passes were built and then removed, deal records turned out to be clean while the rolodex was the mess, and a "stale proposals" purge would have retired live deals. Absence of a flag is not a withheld answer.

### UI
- **ONE QUANTITY, ONE DEFINITION, or the reader trusts none of them.** Three "needs attention" numbers on one screen were 1, 99+ and 197. Two different quantities must be named apart and never summed; a badge cap invents a third. A label written inline on four screens is a label with no owner.
- **A bare em dash at a value's own weight reads as a failed render.** Omit the row, or name the absence in words.
- **When every row is red, red has stopped signifying.** Band it, and reserve the colour for what is still actionable.
- **A control that only appears on hover does not exist on a phone**, and one without `focus-visible:opacity-100` is invisible to a keyboard. Gate the hiding on `sm:`. ⚠ **SAME FOR A WHOLE GESTURE:** build a drag's reducer around a `(lane, index)` move so pointer, arrows and tap-hold all call it, and put the handle BESIDE the card's anchor, never inside. ⚠ **WHICH focus VARIANT IS RIGHT DEPENDS ON WHETHER THE GROUP CAN TAKE FOCUS, so a layout change voids it without touching it** — use `group-focus-within` for a row of buttons, and assert keyboard reveals ≥ hover reveals.
- **A SURFACE HIDDEN BECAUSE IT IS EMPTY IS HIDDEN EXACTLY WHEN SOMEONE NEEDS TO FILL IT.** Count-gating is right for READING a populated record and wrong for the first WRITE: 17 of 19 projects had no meeting, so the only door to logging one sat under "More". Gate for reading; put creating where no count can reach it. And a deep link that promises an open form must be asserted against the pages that actually read the param — a href is a string, so `tsc` sees neither half.
- **A cache in `localStorage` for content that lives in the database is not a cache, it is the only copy the page can see.** Read the stored copy server-side; let the refresh only improve on it.
- **Check whether the data is already on the row before calling a list "an extraction problem".** `/decide` looked like schema work and was a UI change.
- **Fixing a generator changes nothing the reader sees** — the old rows carry the old text. Back them up, then rewrite them.
- **A parent record's value is the sum of its leaves and never its own figure as well**, and parenthood is judged by what is PRESENT in the same set.
- **A shared renderer wired to one surface is worse than no shared renderer.** Grep for a renderer before building one, and for every surface that should call it after — `resolveMeetingTarget` answered the record-matching question properly for a meeting's TITLE while the deals a meeting NAMED still went through a trigram threshold (5 of 52 matched against 20 through the resolver), with a duplicate stopword list drifting beside it. ⚠ **And the THIRD surface was a CONSUMER written for a producer that never existed:** no opportunity could ever be a merge target, so 110 of 126 staged sessions proposed CREATING a record against a register of 26. **Check whether something already consumes the answer you are about to start producing.**
- **A hand-written enumeration beside a registry drifts, and a ⚠ comment saying so does not stop the SIBLING drifting — or the next COMPONENT.** Three times: `/decide`'s chip row, the Documents tab (163 documents its filter could not reach), then `/jobs`. ⚠ **THE FIX THAT ENDS IT IS THE TYPE, NOT THE DERIVATION**: `Record<Kind, …>` in the module that OWNS the vocabulary, so the build names the gap. ⚠ **TYPE THE VALUE TOO** — a tone typed `string` let `amber` through, which `Chip` passes along as CLASS NAMES, rendering unstyled and green. **Where there is no registry, the ROWS are the registry** — derive the filter from the values present, and keep a curated list only for what a human picks from.
- **An untyped string event is a contract nothing checks, and it hides a duplicate of itself.** Four docks opened via `dispatchEvent(new Event('open-…'))` from 8 sites; a rename silently stops opening one and `tsc` cannot see it. Typed registry + a dispatch helper, and check BOTH directions. ⚠ A check matching `new Event(` only missed the two `new CustomEvent(` sites — one of which kept its own second copy of the name.
- **`cn()` is tailwind-merge, so two classes in the SAME utility group do not compose — the later one silently deletes the earlier.** An urgency tint and a cursor highlight were both `bg-*`, so the most urgent row lost its colour exactly when you navigated onto it. `tsc` passes, the build passes, both classes are in the source. Two signals that must show at once go in DIFFERENT groups — a ring, a border, a child. ⚠ **AND A CUSTOM `--text-*` TOKEN IS A COLOUR TO IT**, so `cn('text-metric', 'text-foreground')` drops the SIZE: declare every role in `TYPE_ROLES` (`src/lib/utils.ts`).
- **A sticky element inside a PADDED scroll container needs the padding bled back out** (`-mx-5 sm:-mx-6 px-5 sm:px-6` + an opaque background), or the canvas shows through beside it. Anything sticking below it must clear it — put the bar's height in a token both read.
- **WCAG contrast is the wrong instrument for SURFACE-vs-SURFACE separation — use OKLCH lightness delta.** The ratio's `+0.05` floor swamps real differences at the dark end: a rail at L 0.155 read 1.03:1 against an L 0.13 canvas and still read 1.031:1 at L 0.085. ΔL ≥ 0.03 works at both ends. Keep WCAG for TEXT on a background.
- **A density token moves HEIGHTS, not just gaps — and one of them is the 44px touch target.** `h-11` is `calc(var(--spacing) * 11)`: exactly 44px at the default, 38.7px once tightened, so 66 tap targets shrank below the floor in 32 files with nothing reporting it. Write a touch target absolutely (`h-[2.75rem]`). Before changing a token that feeds a `calc()`, enumerate what else derives from it.
- **A second block for the same selector, further down the file, WINS — and looks like nothing.** New dark elevations sat in the palette block doing nothing while a later `.dark` block kept rendering the old ones. One home per token, with a comment saying it wins.
- **A BRAND COLOUR IS IN THE BRAND ASSET, NOT IN THE TOKEN'S NAME** — `--primary` was commented "Ber Wilson's blue" and defended twice while the logo is terracotta on cream. Sample the asset. ⚠ **And a token themes only what READS it:** gradients, `::selection`, skeletons, `themeColor` and `--chart-*` all bypassed the palette — 2,214 raw colour classes in 135 files. Codemod them (`scripts/codemod/tokenise-colours.mjs`). ⚠ **CHECK WHICH THEME THE USER IS IN before believing a re-skin landed.**
- **A PRIMITIVE ONLY STYLES WHAT USES IT; COUNT THE BYPASSES BEFORE RESTYLING ONE.** 2,214 colour classes bypassed the palette and 274 buttons bypassed `<Button>` (34 files used it), so two sessions' restyling reached almost nothing. ⚠ **A changed DEFAULT also reaches nobody who has used the app: ship a new storage key.**
- **A FILL AND AN INK OF THE SAME LIGHTNESS IS INVISIBLE TEXT, AND NO TYPECHECK SEES IT** — 13 controls shipped white-on-near-white, all green. `bg-foreground` takes `text-background`; `bg-card`/`bg-muted` take `text-foreground`. A shade-based codemod cannot tell a tinted surface from a solid fill — its COMPANION INK can. Asserted in `conventions.test.ts`.
- **AN OPACITY MODIFIER ONLY EVER RIDES A COLOUR UTILITY — elsewhere a `/` is a typo Tailwind drops silently, leaving the fill at full strength.** `bg-primary elev-1/10 text-primary` = 138 invisible buttons, all green. Assert the SHAPE of a modifier, not a slash.
- **IN TAILWIND v4 LAYER ORDER BEATS SPECIFICITY: a `@layer base` rule loses to ANY utility.** A chevron's reserved `padding-right` lost to `px-2.5` on 140 selects, under a comment proving by specificity it could not. Unlayer it; measure the computed value.
- **`overflow-x: auto` AND `overflow: hidden` BOTH MAKE A SCROLL CONTAINER, so a `sticky` child sticks to nothing** — every class correct, inert. Scope the overflow, use `isolate` for a stacking context, and verify by SCROLLING. ⚠ **IT ALSO CLIPS AN `absolute` CHILD** — a dropdown inside a scrollable dialog renders in the right place and is invisible; render it inline there. ⚠ **AND A GRID/FLEX CHILD'S `min-width:auto` MAKES `truncate` INERT until an ancestor has `min-w-0`**, while a `relative` ANCHOR moves when you add a sibling. Three of these in one dialog, all found by DRIVING it, none by a screenshot.
- **A Tailwind class string stored in the database is never generated.** Store a tone NAME against a palette declared literally in source, and reject an unknown tone.
- **A nav item's `alsoMatches` may only name paths with no nav item of their own**, and a filter kept only in component state is not a view — put it in the URL.
- **New UI uses the Panel / Chip / `label-caps` idiom and `.elev-*`, never raw `shadow-*`.** Dates use `DatePicker`. No glassmorphism, colour only for status meaning.
- **Never print a stored enum at a reader** (`enumLabel`), and money is `formatValue`/`formatMoney` — no local copies.

### Working in this repo
- **A test that scans the source tree must STRIP COMMENTS and EXCLUDE ITSELF, or it measures its own documentation.** Both halves cost hours: the only 2 hits for `focus:` are docblocks explaining why it is banned, and a conventions test holds every banned pattern as a regex literal so it reported three false regressions against its own source. - **Two Claude sessions share this repo.** Stage files BY NAME, never `git add -A`; one file holding both sessions' edits goes through a FILTERED PATCH with the dropped hunks counted. ### Reversibility & tests
- **An automatic pass and the undo for it are a LOOP, unless the undo leaves a mark the pass respects.** Reopening a retired commitment restores it to exactly the state the pass selects, so the undo worked once and was overruled every morning after. ⚠ Two runs cannot catch it — the loop needs a human action BETWEEN them.
- **A static check for "is this control labelled" gets broader and wronger — narrow it until it has no false positives**, then plant a violation and prove it still fails. Three versions flagged 20 good buttons, then every `{saving ? 'Saving…' : 'Save'}`, then the multi-line form; the shipped one matches only a child that is exactly one self-closing element. ⚠ **Where the values it hunts are ordinary English words, NO word search can tell a taxonomy from a sentence** — match the enumeration's SHAPE and require two, ADJACENT and comma- or pipe-joined (`'term_sheet'` is also an InvestmentStage). ⚠ `title=` counts toward the accessible name: ignoring it overstated the problem as 34 against a real 17.
- **A test that hardcodes the value it verifies is testing the COPY.** `contrast.test.ts` pasted the palette's oklch values in, so a redraw changed every one and the test kept passing against colours that no longer existed. Read the real artifact. A literal in a test that also exists in source is a duplicate, not a fixture.
- **A worked example whose figures coincide cannot distinguish two readings of the rule it illustrates**, and reproducing it proves only that you matched the coincidence. Ask which of a reference case's inputs are equal by accident, and write the test that pulls them apart. ⚠ Also true of a DERIVED number: a wrong derivation of the attention badge returned 3 against a real 3, by coincidence, so checking the screen against live data would have confirmed the bug. Compute both sides from their own sources and compare.
- **A listed route is not an answering one, and behind auth a curl cannot tell you which it is** — it returns the same redirect either way. Exercise the render directly, for every input shape, and assert no `NaN`, `undefined` or `Infinity` reaches the markup.
- **A fixture that builds the field directly cannot catch a producer that never fills it.** Three tests covered a week-ahead text that could not name a meeting after Monday, because each injected the shape the one-day fetch never produced. Where two consumers want different windows of one feed, give them two FIELDS.
